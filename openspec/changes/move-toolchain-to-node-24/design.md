## Context

Seven GitHub Actions workflows set up Node. Five (`test`, `lint`, `e2e`, `integration`, `package`) request `'24'`; the two docs workflows (`docs-build`, `docusaurus-gh-pages`) request `20`. Three `engines.node` fields exist and none matches the CI matrix: root `>=22.12.0`, `docs/` `>=18.0`, `scripts/` `>=20`. There is no `.nvmrc`. `docs/docs/setup.md` documents Node 22.12+ while noting CI runs 24 — the documentation is accurate about the inconsistency, which is the problem.

The docs site is built by Docusaurus 3.6.3; 3.10.2 is current. A clean `npm ci && npm run build` of 3.6.3 under Node 24 was confirmed to succeed before this change was proposed, so the upgrade is maintenance, not a fix, and the two halves of this change are independent.

Separately, five Lambdas declare `runtime = "nodejs20.x"` in `terraform/aws/` and bundle with esbuild `target: 'node20'`. Those numbers look like the same drift but are not — they name the runtime AWS executes, which is chosen by AWS's support lifecycle, not by what a contributor has installed.

## Goals / Non-Goals

**Goals:**
- One Node major — 24 — stated identically by every `engines.node`, every workflow, and every doc that names a version.
- Docusaurus and its sibling packages on 3.10.2, pinned exactly, lockfile regenerated by npm.
- The rule that Lambda runtime versions are governed separately written down, so the next person raising the toolchain does not sweep `nodejs20.x` along with it.

**Non-Goals:**
- Raising the AWS Lambda runtime or the esbuild targets. Tracked as its own change.
- Adding an `.nvmrc` or any other version-manager file. `engines` plus CI is the enforcement surface for now; adding a fourth place to state the version is the opposite of what this change is for.
- Upgrading React, TypeScript, or any other `docs/` dependency. Only the six `@docusaurus/*` packages move.
- Touching the five app workflows, which already request 24.

## Decisions

**Raise `engines.node` to `>=24.0.0` rather than leaving the floors alone.** The alternative — move CI only — was considered and rejected: it fixes the CI half of the drift while leaving three manifests that permit Node 18/20/22 for a repo where nothing is tested below 24. `engines` is advisory by default (npm warns, it does not block), so the cost of being strict is a warning for anyone who has not upgraded, and the benefit is that the warning names the right version. `>=24.0.0` rather than `^24` because the intent is a floor, not a ceiling; Node 26 should not need a repo-wide edit to be allowed.

**Pin the `@docusaurus/*` packages exactly, not with a caret.** `npm install <pkg>@latest` writes `^3.10.2`; the repo's existing style for these six is a bare `3.6.3`. Exact pins are restored with `npm pkg set` followed by `npm install` so the lockfile matches. The reason to keep them exact is that all six must move together — a caret on `core` and a caret on `theme-mermaid` can resolve to different minors on different machines, which is precisely the class of drift this change exists to remove.

**Upgrade Docusaurus in the same change as the Node pin, despite being independent.** They touch the same two workflows and the same `docs/package.json`, and both are verified by the same command (`npm ci && npm run build` in `docs/`). Splitting them would mean two PRs that each regenerate `docs/package-lock.json` and conflict with each other. The rollback story stays clean because the Docusaurus half is confined to `docs/package.json` and `docs/package-lock.json` and can be reverted without touching the Node pins.

**Write the Lambda-runtime exclusion into the spec as a requirement, not just a note in the proposal.** A proposal is archived; a spec is the standing contract. The requirement states both halves of the rule — the toolchain change must leave the runtimes alone, and a runtime change must move Terraform and esbuild together — so the coupling that does matter is recorded alongside the one that does not.

## Risks / Trade-offs

- **Docusaurus 3.6.3 → 3.10.2 spans four minors; theme internals may have shifted.** → Verify with a clean `npm ci` (not an incremental install) plus a real browser check of the three things most likely to regress: the navbar logo, the architecture SVGs, and the mermaid diagrams, which come from `@docusaurus/theme-mermaid` — the package with the most rendering surface in this jump. The gh-pages workflow publishes the site, so a regression that escapes local checks is visible on the live site rather than silently wrong.
- **`engines.node >=24.0.0` breaks nobody's build but annoys contributors on 22.** → It is a warning, not an error, and the docs are updated in the same change so the requirement is discoverable before the warning appears. Node 22 is still in maintenance, so anyone affected has a supported upgrade path.
- **A future contributor sees `nodejs20.x` next to a Node 24 toolchain and "fixes" it.** → The spec requirement above says explicitly that the two are governed separately, and the follow-up change gives the runtime bump a home.
- **The docs lockfile regenerates wholesale, making the diff large.** → Unavoidable and expected for a dependency upgrade; the reviewable surface is `docs/package.json`, and CI's `npm ci` proves the lockfile is coherent.

## Migration Plan

1. Upgrade the six `@docusaurus/*` packages via npm, restore exact pins, let npm regenerate `docs/package-lock.json`.
2. Change `node-version` to `'24'` in both docs workflows; raise the three `engines.node` floors.
3. Update the Node versions stated in `setup.md`, `maintainer.md`, and `submodule.md`.
4. Verify locally on Node 24: clean `npm ci && npm run build` in `docs/`, then a running site checked for logo, SVG diagrams, and mermaid rendering.
5. Open the PR; `docs-build.yml` runs the same verification on Node 24 in CI. Merge exercises `docusaurus-gh-pages.yml` against the live site.

Rollback: revert the whole commit, or revert only `docs/package.json` + `docs/package-lock.json` to keep the Node pins and drop the Docusaurus upgrade.

## Open Questions

None. The two decisions that could have gone either way — whether to raise `engines` at all, and whether to fold in the Docusaurus upgrade — were settled before planning.
