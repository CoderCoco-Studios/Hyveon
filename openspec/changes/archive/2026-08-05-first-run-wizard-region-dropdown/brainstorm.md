# Brainstorm: First-Run Wizard AWS Region Dropdown

## Starting question

> What would it take for the first run wizard AWS region setup to be a
> dropdown selection that contains the available AWS regions and their
> physical location? Is there an AWS API that could be called to figure
> this out?

## Context gathering

Dispatched two parallel research agents:

1. **Codebase exploration** (`Explore`, opus) — found all AWS region inputs
   in `@hyveon/web`:
   - `credentials-step.component.tsx:180-186` (profile mode) — free-text
     `<Input>`.
   - `credentials-step.component.tsx:211-217` (paste mode) — free-text
     `<Input>`.
   - `guided-iam-step.component.tsx:474-486` (region phase) — free-text
     `<Input>`.
   - `guided-iam-step.component.tsx:604-612` (intake phase) — free-text
     `<Input>`.
   - `deployment-settings-form.component.tsx:399-405` — free-text
     `TextField`, outside the wizard.
   - No React Hook Form / Zod in `@hyveon/web`; everything is plain
     `useState` lifted to the parent (`first-run-wizard.component.tsx:111`).
   - No existing AWS region array/enum anywhere in the repo.
   - `GuidedIamService` (`desktop-main`) explicitly runs **before** any
     credential source exists — confirmed the `guided-iam-step` region
     phase has no AWS credentials available yet.
   - Validation today is emptiness-only
     (`first-run-wizard.component.tsx:630-633`); the only format check
     anywhere is a URL-safety regex in
     `GuidedIamService.buildCloudFormationConsoleUrl`.
   - Region is persisted via `wizard.saveState` → `ConfigService.getRegion()`
     as the synchronous source for AWS SDK client construction.

2. **AWS API research** (`claude-code-guide`, opus) — evaluated three
   sources for region code → physical-location data:
   - `EC2 DescribeRegions` — needs credentials (`ec2:DescribeRegions`),
     returns country only (`"United States of America"`, not
     `"N. Virginia"`), 34 commercial regions with `--all-regions`.
   - SSM public parameters
     (`/aws/service/global-infrastructure/regions/...`) — confirmed **not**
     truly anonymous: unsigned calls get
     `MissingAuthenticationTokenException`; signed calls with the repo's
     deploy user get `AccessDeniedException` (no `ssm:GetParametersByPath`
     grant in `HyveonDeployAll` today). Returns `longName` per region but
     requires N+1 calls (list + one per region).
   - AWS static JSON
     (`https://b0.p.awsstatic.com/locations/1.0/aws/current/locations.json`)
     — public, unauthenticated, ~2.5 KB, 38 regions with `code`/`name`/
     `continent`, e.g. `us-east-1` → `"US East (N. Virginia)"`. HTTP 200
     with no auth.
   - Recommendation: bundle a static code→label map generated at build
     time from the AWS JSON, committed like the generated icons — the only
     option that works before the user has entered any credentials.

## Decision chain

**Q1 — Which of the 4 region inputs should become the dropdown?**
A: Only `guided-iam-step.component.tsx`'s `phase === 'region'` screen —
the main pre-credentials region picker most users hit first. The other
three stay free-text.

**Q2 — How should the region→label data get into the repo?**
A: A committed static map, regenerated by a manually-triggered script
(same pattern as `icons:generate`) — not fetched live at runtime. User
flagged one requirement while approving this: since the map isn't always
current, the wizard must still let a user enter a region directly if it's
missing from the map (new regions shouldn't be blocked by a stale
generated file).

**Q3 — How should the manual-entry fallback work in the UI?**
A: `"Other (enter manually)"` as the last dropdown item. Selecting it swaps
the Select for a text input, pre-focused, same validation as today.

**Q4 — Which regions should the static map include?**
A: Commercial partition only (~34-38 regions). GovCloud/China aren't
reachable via Hyveon's guided IAM flow anyway; they'd only be accessible
via manual entry if ever needed.

**Q5 — How should each dropdown entry display?**
A: `"US East (N. Virginia) — us-east-1"` — friendly name first, region
code visible in the same line for users who already know the code.

**Q6 — Where should the generated region-map file live?**
A: `@hyveon/shared` — not web-UI-specific, keeps it reusable if
`desktop-main` or another package ever needs region labels, consistent
with how `canRun()`-style shared logic is placed.

**Q7 — How should the dropdown list be ordered?**
A: Grouped by continent, alphabetical by name within each group — more
scannable for someone who knows their rough geography but not the exact
city name.

## Codebase details confirmed by direct reads (not the research agents)

- `guided-iam-step.component.tsx:461-499` — the exact region-phase JSX
  block to be replaced (label, `<Input>`, `regionError`, buttons).
- `credentials-step.component.tsx:163-175` — the wizard's profile picker
  uses a **plain native `<select>`**, not the shadcn Select component.
- `app/packages/web/src/components/ui/select.component.tsx` — a full
  shadcn/Radix `Select` (`Select`, `SelectGroup`, `SelectLabel`,
  `SelectItem`, etc.) already scaffolded in the repo, backed by
  `@radix-ui/react-select` (already a dependency), but **not imported
  anywhere** in the app today. Using it here would be its first real
  usage — supports the `SelectGroup`/`SelectLabel` primitives needed for
  continent grouping directly.
- `app/packages/shared/src` — flat file layout (`deploymentConfig.ts`,
  `canRun.ts`, `gameServerConfig.ts`, etc.), `index.ts` as the barrel
  export — the generated `awsRegions.ts` follows this same flat
  convention.
