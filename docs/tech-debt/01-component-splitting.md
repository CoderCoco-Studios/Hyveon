# 01 — Oversized React components

## Summary

`app/packages/web` is ~15k lines of TSX across 65 non-test components, and the debt is concentrated in six files that account for ~4,400 of them: `discord.page.tsx` (1259), `iac.page.tsx` (1213), `first-run-wizard.component.tsx` (986), `guided-iam-step.component.tsx` (779), `deployment-settings-form.component.tsx` (665), and `networking-step.component.tsx` (544).
The dominant pattern is **not** the classic "inline render helper" smell — there are zero `renderX` helpers in the codebase and several files (`discord.page.tsx`, `iac.page.tsx`) are already internally decomposed into well-named sub-components that merely share one file. The two patterns that actually cost maintenance are (a) **single component functions of 400–900 lines** that fuse an IPC/state machine with its presentation (`GuidedIamStep` ~660 lines, `FirstRunWizard` ~875, `IacPage` ~580, `NetworkingStep` ~450), and (b) **copy-pasted micro-JSX with no shared primitive** — 21 hand-inlined label+input+error triads, 15 identical `role="alert"` red paragraphs, 10 page headers, 8 error banners, 7 raw `<select>` elements with a drifted class string, 37 inline `animate-spin` spinners, and `formatTimestamp` duplicated verbatim in 4 files.
Test coverage is unusually good and is what makes this tractable: every non-`ui/` component has a co-located jsdom spec, and all Playwright specs reach elements through page objects in `app/packages/web/e2e/pages/`, so a split that preserves DOM roles and exact text strings is low-risk. The notable gaps are the add-game wizard and the first-run wizard's bootstrap step, which have **no e2e coverage at all**.
Rough total: ~40 findings, **12–16 working days** across **18 PRs**, front-loaded on four cheap shared-primitive PRs that the rest depend on.

## Rules to add or update

**1. New section in `.claude/rules/typescript-conventions.md` — "Component size and extraction":**

> A component function body over ~200 lines, or holding more than ~8 `useState`/`useEffect` calls, must be split before the PR opens. Two cuts, in this order: (a) move the data/IPC orchestration into a `use-*.hook.ts` beside the component, leaving a presentational body; (b) extract any `.map()` callback whose JSX body exceeds ~15 lines into a named child component. A file may hold several small related components, but the *file* should be split into a directory once it passes ~400 lines.
>
> **Why:** `first-run-wizard.component.tsx`, `guided-iam-step.component.tsx`, `iac.page.tsx` and `networking-step.component.tsx` each grew to a single 450–900-line function fusing a state machine with its markup; the cost is that every one of them now needs a multi-day extraction with a real regression risk, where an incremental split would have been free.

**2. New section in `.claude/rules/typescript-conventions.md` — "Reach for a primitive before pasting markup":**

> Before hand-writing a label+input+error group, a `role="alert"` paragraph, a page header, a status pill, an empty state, or a spinner, check `app/packages/web/src/components/ui/` and `app/packages/web/src/components/` for an existing primitive. If none exists and this would be the **third** copy of the shape, extract the primitive in the same PR rather than pasting. Never copy a Tailwind class string longer than one line between files — extract it.
>
> **Why:** the third-copy rule is exactly where drift starts. The 7 raw `<select>` elements in `networking-step.component.tsx` copied a class string that has since diverged from `ui/input.component.tsx` (no focus ring); the `role="alert"` red paragraph exists 15 times identically; `formatTimestamp` is byte-identical in 4 files; and `deployment-settings-form.component.tsx:591-593` *documents* its duplication of `SnowflakeChipsInput` instead of resolving it — with the copy having silently lost snowflake validation.

**3. Addition to `.claude/rules/testing-conventions.md` — "Playwright conventions", as item 5:**

> Locators must be semantic, never positional. `page.locator('input[readonly]').nth(1)` breaks silently under any DOM reorder; give the element an `aria-label` or `data-testid` and target that.
>
> **Why:** `e2e/pages/GuidedIamWizardPage.ts`'s `consoleUrlFallbackInput()` is currently positional and documents its own dependence on the template screen's render order — it will pass-but-target-the-wrong-element the moment that screen is split.

**4. Addition to `.claude/rules/testing-conventions.md` — "Refactor safety", new short section:**

> A pure component extraction (no behaviour change) must keep the DOM's accessible surface byte-identical: heading levels, ARIA roles and landmarks, `data-testid` values, and any exact-match text a page object queries. Run `npm run app:test:e2e` before claiming a split is safe — the jsdom suite will not catch a lost `role="alert"` or a changed heading level.

**5. Optional lint guardrail (`app/eslint.config.js`):** there is currently no `max-lines`, `max-lines-per-function`, or `complexity` rule. Adding `'max-lines-per-function': ['warn', { max: 250, skipComments: true, skipBlankLines: true }]` scoped to `**/*.tsx` would surface rule 1 mechanically. Propose as `warn`, not `error` — six existing files would trip it on day one, which is the point, but it should not block CI until they are fixed.

## Method

Seven sub-agents, all read-only. One **sonnet** mechanical sweep produced the full 65-file inventory (line counts, hook counts, `.map()` callback spans, `renderX` helpers, co-located-spec presence) — which is what established that zero `renderX` helpers exist and that only 13 `.map()` bodies exceed 12 lines. One **sonnet** agent mined all 132 PRs touching `.tsx` (~1,900 review + issue comments from CodeRabbit, Copilot, and humans) for size/split feedback and found **none** — every keyword hit was a false positive from CodeRabbit's own embedded analysis scripts. It did surface three prior self-reported extractions (`LogLineList` in PR #537, `JumpToLatestButton` in PR #538, `saveWizardState` in PR #439), which establish in-repo precedent for the shared-primitive findings. Five **opus** judgment agents took one slice each: discord page; iac + logs pages; first-run wizard; add-game wizard + forms + settings; and app shell + dashboard/games/costs/diagnostics. I verified every `file:line` cited above by reading the actual lines — 14 independent spot-checks, all confirmed, including the byte-identical `RunsTableRow`/`DeploymentConfigRow` pair, the four-way `formatTimestamp` duplication, the `SnowflakeChipsInput` self-documenting comment, the empty-Client-ID path through `DiscordConfigService`, and `CardTitle`'s `<h3>` element (which the `games.spec.ts` heading-level locator depends on).
