# 02 — Doc-comment bloat and gaps

## Summary

25.4% of the TypeScript tree is comment — 27,648 block-comment lines plus 5,162 `//` lines against 129,071 LOC across 486 files — and the great majority of that mass is bloat rather than documentation.
The rubric in `.claude/rules/tsdoc-tags.md` is, surprisingly, already satisfied almost everywhere: a scripted repo-wide sweep found **zero** `@fileoverview`, **zero** invented tags (`@note`/`@warning`), **zero** `@param {Type}` JSDoc-style params, **zero** bare `@link`, exactly **one** tag-ordering violation, and export doc coverage of 99% (952/964) — so there is essentially no mechanical TSDoc-syntax debt to pay, and the `@param game - the game` pattern the audit anticipated does not occur at all (a scripted check for descriptions that are a subset of the parameter name returned 0 hits).
The debt is entirely against `.claude/rules/comment-conciseness.md`: TSDoc blocks written as design-review memos (a single 402-line block on `PulumiService.apply()`), vendored Go and `@pulumi/pulumi` source pasted into comments to prove claims the surrounding sentence already states, 197 lines of history narration, 174 issue/PR/phase references, 249 Terraform HCL-address citations in `infra` pointing at a tree the comments admit was deleted, 234 ASCII `-----` banner lines, and the same explanation retold verbatim in up to five files.
Against that, the genuine **add** cases are few but sharp: six `AWS_REGION_` reads with no note that the trailing underscore is load-bearing, the Caddy sidecar block with no statement of the no-ALB invariant, `canRun()` with no never-fork rule, and an invisible raw NUL byte used as a dedupe separator.
Total effort ≈ **9–11 engineer-days** across **12 PRs**; roughly 6,000–7,000 comment lines removable with zero behaviour change.

## Rules to add or update

The good news is that `eslint-plugin-jsdoc@63.3.0` is already installed (`app/eslint.config.js:5,47`) and already enforces `jsdoc/require-jsdoc` with `publicOnly: true`, which is why coverage is 99%. Four more rules from the same plugin — all verified present in the installed version — would mechanically enforce rules that `tsdoc-tags.md` currently says are "review-enforced, don't eyeball them either", and one of them enforces exactly the restatement rule this audit was asked to look for.

### 1. `app/eslint.config.js` — enforce TSDoc tag ordering

```js
'jsdoc/sort-tags': ['error', {
  tagSequence: [{ tags: ['remarks', 'example', 'typeParam', 'param', 'returns', 'throws'] }],
}],
```

Why: `tsdoc-tags.md` rule 1 is currently unenforceable by hand — this audit found the violations (`SafeStorageService.ts:62`, plus two double-`@remarks` blocks) only by script. The repo is already at one violation, so this rule goes green after PR-10 and stays green for free.

### 2. `app/eslint.config.js` — ban non-TSDoc tags by allowlist

```js
'jsdoc/check-tag-names': ['error', {
  definedTags: [
    'remarks', 'example', 'typeParam', 'param', 'returns', 'throws',
    'defaultValue', 'see', 'privateRemarks', 'packageDocumentation',
    'deprecated', 'override', 'sealed', 'virtual', 'internal', 'alpha', 'beta', 'public',
  ],
  jsxTags: false,
}],
```

Why: `tsdoc-tags.md` rules 2 and 3 forbid `@note`, `@warning` and `@fileoverview`. The repo currently has zero of them — but nothing keeps it that way, and `tsdoc/syntax` does **not** catch a syntactically valid but non-TSDoc tag. This rule locks in a clean state at zero migration cost.

### 3. `app/eslint.config.js` — require a summary before the first block tag

```js
'jsdoc/require-description': ['error', { descriptionStyle: 'body' }],
```

Why: this is the one structural defect class the audit actually found — 11 blocks that open directly with `@param` and never say what the thing is (finding E-7). Enable it in the same PR that fixes those 11 (PR-12), not before.

### 4. `app/eslint.config.js` — flag doc text that only restates the identifier

```js
'jsdoc/informative-docs': 'warn',
```

Why: this is the plugin's rule for exactly the `@param game - the game` / `/** The value to persist. */` pattern (findings A-29, E-15). Land it as `warn` first: it uses a word-overlap heuristic and will have false positives on this codebase's `hyveon-api.ts` field docs, which are legitimate. Promote to `error` only once the warning count is at zero.

Not proposed: a rule for `@param name - description` hyphen style (`jsdoc/require-hyphen-before-param-description` exists, but the repo is already at 100% compliance and the rule adds noise for no gain), and any lint rule for comment *length* — no plugin rule covers it, and a custom rule capping doc blocks at N lines would fight comment-conciseness rule 5, which explicitly entitles complex functions to long TSDoc. Length stays a review judgement.

### 5. `.claude/rules/comment-conciseness.md` — add a "no archaeology" clause

Append as rule 6:

> 6. **Comments describe the code as it is, not how it got here.** No issue/PR numbers, no phase or task numbers, no "previously / originally / used to / no longer / renamed from", and no references to files, tools or code that no longer exist in the tree. `git blame` and the PR history already carry provenance, and a comment that defines current behaviour by contrast with something deleted is unreadable to anyone who never saw the deleted thing. Where a past decision left a *live* constraint — a resource name that must stay stable, a message string a caller matches on, a derivation that must not change or resources get replaced — state the constraint in the present tense and drop the history that produced it.

Why: this is the single dominant pattern in the audit — 197 history lines, 174 issue references and 249 Terraform citations, i.e. the majority of every sweep PR above. The existing rule bans verbosity but never bans archaeology, so nothing in the rubric today would have stopped `program.ts:1`'s 95-row inventory of a tree the comment admits was deleted.

### 6. `.claude/rules/comment-conciseness.md` — add a "say it once" clause

Append as rule 7:

> 7. **One canonical explanation per constraint.** When the same rationale applies in several files, write it in full in the one place that owns it and link there from the others (`{@link Symbol}`, or a path to the `docs/docs/**` page that carries the reasoning). Never restate it. A constraint explained in five files drifts in four of them.

Why: the ESM module-cycle story is told in five module files (B-3), the credential-signature paragraph five times in `cloud-aws` (E-8), the runs-table invariant four times in `infra` (D-6), the `HashRouter` rationale four times in `web/e2e` (C-7), and the streaming-mock digression three times in `web` (C-8). `infra`'s copy has already drifted — `lambdas.ts:1` says five Lambdas where the code and docs say six.

### 7. `CLAUDE.md` — fix the Lambda count

Three places say "five Lambda packages" (`CLAUDE.md:16`, `:39`, `:52`) where there are six (`app/packages/lambda/` has `efs-seeder`, `followup`, `health-check`, `interactions`, `update-dns`, `watchdog`; `docs/docs/components/lambdas.md:8` correctly says six; `package.json:38`'s typecheck script lists all six by name). Since CLAUDE.md is the authority the rest of the tree copies from, this error has already propagated into `infra/src/lambdas.ts:1`.

## Bugs found incidentally

1. **`app/packages/web/src/components/add-game-wizard/wizard-form.utils.ts:555` — a raw NUL byte in TypeScript source.** The dedupe key is built as `` `${issue.path}<NUL>${issue.message}` `` with a literal U+0000 embedded in the template literal rather than a `\0` escape. Consequences: `file(1)` reports the source as `data`, GNU grep refuses to search it ("binary file matches") so the file silently drops out of every text sweep, and the separator is invisible in editors and diffs. Fix: replace the raw byte with `'\0'` (behaviour-identical) and add the explanatory comment from C-17. Effort S; `wizard-form.utils.test.ts` covers `dedupeIssues`. It is the only file in the 486-file tree containing a NUL byte.

2. **`app/packages/desktop-main/src/services/PulumiService.ts:791` — a corrupted doc comment.** A paragraph inside `stackInitInFlight`'s TSDoc begins mid-sentence: `* set (see its own TSDoc, "Workspace mutual exclusion"), and`. Its subject was lost in an edit, so the sentence explaining which flag blocks `initializeStack` is unreadable. This is documentation of a real mutual-exclusion invariant, so the loss is material. Fix: restore the clause or delete the fragment. Effort S; `PulumiService.initializeStack.test.ts`.

3. **`app/packages/desktop-main/src/services/EcsService.ts:381` — latent secret leak into the log file.** `logger.error('RunTask failed', { reason, failures: resp.failures, params })` logs the entire `RunTaskCommandInput`, whose `overrides.containerOverrides[].environment` can carry operator-supplied secrets. This violates `.claude/rules/logging.md` rule 3 ("never log raw payloads that might carry them"). **Verified not currently exploitable**: the sole production caller (`FileManagerService.ts:269`) passes no `overrides`, and no code in `desktop-main` or `cloud-aws` sets `containerOverrides`. It is a trap armed for the first caller that does. Fix: log `taskDefinition`/`cluster`/`startedBy` only, and add a one-line note so it is not reintroduced. Effort S; `EcsService.test.ts`.

## Method

I ran the mechanical layer myself rather than delegating it, because the whole-tree scans (TSDoc tag inventory, tag-ordering check, export doc-coverage, block-comment size distribution, duplicate-sentence detection, NUL/encoding check) are cheaper as five Python passes over a single 486-file list than as sweep agents, and they produced the negative results that shaped everything else — discovering that `tsdoc-tags.md` is already ~99.9% satisfied redirected all five judgement agents away from tag hunting and toward `comment-conciseness.md`, which is where the debt actually is.
I then fanned out **five Opus judgement agents** by package group, sized by comment mass rather than file count: (1) `desktop-main/src/services` alone (10,726 block-comment lines — a third of the repo's total), (2) the rest of `desktop-main` plus `.claude/hooks` and the root test configs, (3) `infra` + all six `lambda/*` packages (grouped because both carry the invariants and share the Terraform-migration history), (4) `shared` + `desktop-preload` + `cloud-aws` (the three highest comment-to-code ratios, 21–33%), and (5) `web`. Each received `.claude/rules/comment-conciseness.md` and `tsdoc-tags.md` verbatim plus CLAUDE.md's invariant list as its rubric, the pre-computed inventory of its own ≥8-line blocks, and an explicit instruction not to re-derive the mechanical negatives. Agents were read-only and returned tables, not files. No Sonnet sweep agents were used — the scripted passes covered that tier better.
I spot-verified ~25 claims across all five agents with `sed`/`grep` — including every finding I have quoted in the Bugs section and every **add** finding — and all held; I corrected two agent claims (the "12 undocumented NestJS `@Module` classes", which was my own script's decorator-lookback false positive and which agent 2 independently caught, and the `iac-run-detail.page.tsx` `fetch()` "bug", which is a legitimate presigned-URL fetch). Site counts quoted in the Summary tables are from my scripts, not from agent estimates.
**Not covered:** `.tsx` snapshot/fixture data files were scanned but not judged line by line; Markdown comments in `openspec/**` and `docs/**` are out of scope (they belong to the docs-accuracy audit); and I did not run `npm run app:lint` to confirm the tree is currently green, since the audit is read-only and lint state is the PR author's gate rather than a finding. The 402-, 283- and 206-line `PulumiService.ts` blocks were read in full by agent 1 and their target line counts are its judgement, spot-checked by me at the block boundaries only.
