# IaC Engine Specs

EARS requirements for prefix `IAC-ENGINE`, the leaf described in `docs/intent/iac/engine/engine-design.md`.

## Engine provisioning

- [x] **IAC-ENGINE-PROV-001**: When an infrastructure operation is requested and the engine cache under Electron `userData` holds no install of the pinned version, `PulumiEngineService` shall download and install the pinned Pulumi engine into that cache before the operation runs, with no operator-installed tooling required. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-002**: `PulumiEngineService` shall resolve the engine from its app-owned cache and shall not probe `PATH` for a `pulumi` binary. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-003**: When an infrastructure operation is requested and a verified install of the pinned engine version is already present in the cache, `PulumiEngineService` shall reuse it without downloading. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-004**: When two callers request the engine before provisioning has completed, `PulumiEngineService.resolve` shall share one memoised provisioning attempt so exactly one download is performed and both callers receive the same engine. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-005**: If a memoised engine provisioning attempt rejects, then `PulumiEngineService.resolve` shall discard the memo so the next call starts a fresh attempt instead of replaying the failure. (observed)
- [x] **IAC-ENGINE-PROV-006**: `PulumiEngineService.resolve` shall emit an `('engine','start')` and `('engine','end')` phase event pair to every caller that supplies a phase callback, including a caller that joins an in-flight attempt and a caller whose attempt fails. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-007**: The engine cache root shall resolve, in order, to `HYVEON_PULUMI_ENGINE_DIR`, then `<userData>/pulumi`, then an `os.tmpdir()` fallback for plain-Node contexts, with each pinned version installed under `<root>/versions/<pin>`. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-008**: When the Nest application context is constructed on a machine with no engine installed and no network, `PulumiEngineService` shall instantiate without performing any engine work, so a provisioning failure surfaces only when an operation is attempted. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-PROV-009**: When `PulumiService.initializeStack` runs, it shall report the cloud provider plugin install as a `plugins` phase distinct from the `engine` phase and the `operation` phase. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [ ] **IAC-ENGINE-PROV-010**: When `preview`, `apply` or `destroy` is the first operation on a machine whose plugin cache is empty, the system shall report the provider plugin download to the caller as its own phase rather than as part of the operation. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning) (gap: only `initializeStack` emits a `plugins` phase, `PulumiService.ts:1151-1161`; preview/apply/destroy stream no phase events)
- [x] **IAC-ENGINE-PROV-011**: The engine install and its provider plugins shall land under app-owned directories derived from Electron `userData` (`<userData>/pulumi` for the engine, `<userData>/pulumi-workspace/home` as `PULUMI_HOME` for plugins), never under a shared user-level `~/.pulumi`. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [ ] **IAC-ENGINE-PROV-012**: When a successful engine provisioning prunes superseded versions, `PulumiEngineService` shall also reclaim `.staging-` and `.trash-` directories left behind by an earlier crashed install. (observed) (gap: `PulumiEngineService.ts:622` skips every `.staging-`/`.trash-` entry)

## Engine version pin

- [x] **IAC-ENGINE-PIN-001**: The Pulumi engine version shall be pinned to the single constant `PULUMI_ENGINE_VERSION` exported from `@hyveon/shared` (`pulumiVersion.ts`). (OpenSpec: pulumi-engine-runtime / Pinned engine version)
- [x] **IAC-ENGINE-PIN-002**: `PulumiEngineService` shall accept an installed or cached engine only when its version equals `PULUMI_ENGINE_VERSION` exactly, rejecting a newer version that the SDK's own minimum-version check would accept. (OpenSpec: pulumi-engine-runtime / Pinned engine version)
- [x] **IAC-ENGINE-PIN-003**: When the engine cache holds a version other than the pin, `PulumiEngineService` shall provision and use the pinned version in its own version-namespaced directory and shall not use the stale version for the operation. (OpenSpec: pulumi-engine-runtime / Pinned engine version)
- [x] **IAC-ENGINE-PIN-004**: When the pinned engine has been provisioned and verified, `PulumiEngineService` shall prune the directories of superseded pinned versions from the cache on a best-effort, never-throwing basis. (observed)
- [x] **IAC-ENGINE-PIN-005**: When the renderer requests the engine status after a successful provisioning, the `iac.settings.engineVersion` channel shall return the resolved engine version, equal to `PULUMI_ENGINE_VERSION`, from `PulumiEngineService.getResolvedVersion()`; before the first success it shall report no resolved version. (OpenSpec: pulumi-engine-runtime / Pinned engine version)

## Engine provisioning failure

- [x] **IAC-ENGINE-PFAIL-001**: If engine provisioning fails, then `PulumiEngineService` shall throw exactly one typed error naming the cause: `PulumiEngineNetworkError` for connectivity failures, `PulumiEngineIntegrityError` for download or verification failures, or `PulumiEngineCacheWriteError` for an unwritable cache. (OpenSpec: pulumi-engine-runtime / Engine provisioning failure is actionable)
- [x] **IAC-ENGINE-PFAIL-002**: `PulumiEngineService` shall install a fresh engine into a sibling `.staging-<uuid>` directory and swap it into the version directory only after verification, so an interrupted or failed install never leaves partial content at the path a later run treats as the installed engine. (OpenSpec: pulumi-engine-runtime / Engine provisioning failure is actionable)
- [x] **IAC-ENGINE-PFAIL-003**: When a fresh engine install replaces an existing cache entry that failed only an ambiguous check, `PulumiEngineService` shall rename the prior entry aside to `.trash-<uuid>` rather than delete it, and if the swapped-in install fails re-verification shall remove it and restore the prior entry. (observed)
- [x] **IAC-ENGINE-PFAIL-004**: If a cached engine entry fails verification with positive evidence of corruption, then `PulumiEngineService` shall delete it and reprovision; if the failure is inconclusive, then it shall leave the entry in place and reprovision fresh. (observed)
- [x] **IAC-ENGINE-PFAIL-005**: When stack initialization fails during engine provisioning, the failure shall reach the wizard as a `PulumiStackInitializationError` attributed to the `engine` phase, and the wizard shall show the error with a retry rather than crashing the main process. (OpenSpec: pulumi-engine-runtime / Engine provisioning failure is actionable)
- [ ] **IAC-ENGINE-PFAIL-006**: When `PulumiEngineService` logs a caught provisioning, pruning or restore error, it shall log the normalised error message rather than the raw error object. (observed; `.claude/rules/logging.md`) (gap: raw `err` logged at `PulumiEngineService.ts:446,453,618` and `restoreErr` at `:528-532,572-576`)

## Workspace seam

- [x] **IAC-ENGINE-WS-001**: Every Pulumi stack used by `PulumiService` (outputs read, stack initialization, preview, apply, destroy, rollback, lock clear) shall be constructed through the single seam `PulumiWorkspaceService.getOrCreateStack`. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-002**: `PulumiWorkspaceService.getOrCreateStack` shall configure the engine with the DIY S3 backend `s3://<stateBucket>?region=<stateBucketRegion>` via `PULUMI_BACKEND_URL`, `AWS_REGION` set to the same region, and `PULUMI_SKIP_UPDATE_CHECK`, requiring no Pulumi Cloud login or access token. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-003**: If `getOrCreateStack` is called with `backendReady: false`, then it shall throw `PulumiBackendNotBootstrappedError` before any engine work and shall not create the state bucket. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-004**: If stack creation or selection fails because the state bucket does not exist, then `getOrCreateStack` shall rethrow the failure as `PulumiBackendNotBootstrappedError` directing the operator to the bootstrap step. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-005**: `getOrCreateStack` shall reuse one stable workspace per install, `<root>/home` as `PULUMI_HOME` and `<root>/workspace/production` as the work directory, where root is `HYVEON_PULUMI_WORKSPACE_DIR`, `<userData>/pulumi-workspace`, or a tmpdir fallback, so the number of workspace directories does not grow with the number of operations. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-006**: `getOrCreateStack` shall create or select the stack under the bare name `production` with an inline program, never an `organization/<project>/<stack>` name or a `workDir` program. (observed)
- [x] **IAC-ENGINE-WS-007**: When `getOrCreateStack` successfully creates or selects the stack, it shall set the non-secret `pulumi.stackInitialized` marker in the electron store. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-008**: If stack creation or selection fails in `getOrCreateStack`, then the `pulumi.stackInitialized` marker shall be left unchanged (unset if never set, still set if set by a prior success). (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-009**: The `pulumi.stackInitialized` marker shall hold only a boolean and shall never be used as or stored alongside a passphrase value. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-WS-010**: The state backend region passed to `getOrCreateStack` shall be the wizard region, electron-store `aws.region`, which is the region bootstrap creates the state bucket in (`PulumiService.ts:988,1126,1611,2270,2928,3709`; `BootstrapService.ts:605-617`). (observed)

## Secrets passphrase

- [x] **IAC-ENGINE-PASS-001**: `getOrCreateStack` shall configure the `passphrase` secrets provider and supply `PULUMI_CONFIG_PASSPHRASE` in the engine environment for every stack it creates or selects, including the first creation. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-PASS-002**: `getOrCreateStack` shall derive the stack passphrase as an HMAC-SHA256 over the AWS account id (from a live `sts:GetCallerIdentity`) and the stack name with a fixed app-level constant, recomputed on every call and never written to local storage. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-PASS-003**: When an operation runs on a second machine holding valid credentials for the same AWS account and no stored passphrase, `getOrCreateStack` shall derive the same passphrase the stack was created with and complete the operation. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-PASS-004**: If `sts:GetCallerIdentity` fails while deriving the passphrase, then `getOrCreateStack` shall log a warning with the normalised message and throw a plain `Error` carrying only that message. (observed)
- [x] **IAC-ENGINE-PASS-005**: When `getOrCreateStack` runs on an install whose store still holds a legacy `pulumi.passphrase`, it shall re-encrypt the stack's secrets provider to the derived passphrase via `pulumi stack change-secrets-provider` and only then remove `pulumi.passphrase` from the store, with no operator action. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-PASS-006**: If the legacy passphrase re-encryption fails, then `getOrCreateStack` shall leave `pulumi.passphrase` in place so the next workspace construction retries the migration with the same legacy value. (OpenSpec: pulumi-engine-runtime / Automation API workspace seam)
- [x] **IAC-ENGINE-PASS-007**: If a legacy `pulumi.passphrase` is stored while the OS keychain is unavailable, then `getOrCreateStack` shall throw an operator-actionable error telling the operator to unlock the keychain, without attempting to decrypt or migrate. (observed)
- [ ] **IAC-ENGINE-PASS-008**: If the legacy passphrase migration cannot run because the workspace directory no longer holds a `Pulumi.yaml` from a prior run, then the system shall offer the operator a recovery path rather than failing every `getOrCreateStack` call. (observed) (gap: documented dead end with manual reset only, `PulumiWorkspaceService.ts:522-591`)

## Credentials

- [x] **IAC-ENGINE-CRED-001**: When `getOrCreateStack` is not given explicit credential variables, it shall resolve the wizard-selected AWS credential source itself via `resolveCredentialEnvVars`, so the engine never falls back to its own default credential chain. (OpenSpec: pulumi-engine-runtime / Wizard-selected credentials reach the engine)
- [x] **IAC-ENGINE-CRED-002**: Where the wizard-selected credential source is a named profile, `resolveCredentialEnvVars` shall set `AWS_PROFILE` to that profile and set `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN` to empty strings so ambient values cannot override it. (OpenSpec: pulumi-engine-runtime / Wizard-selected credentials reach the engine)
- [x] **IAC-ENGINE-CRED-003**: Where the wizard-selected credential source is pasted keys, `resolveCredentialEnvVars` shall set `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` from the decrypted store values in the main process and set `AWS_SESSION_TOKEN`, `AWS_PROFILE` and `AWS_DEFAULT_PROFILE` to empty strings. (OpenSpec: pulumi-engine-runtime / Wizard-selected credentials reach the engine)
- [x] **IAC-ENGINE-CRED-004**: If no AWS credential source is configured, then `resolveCredentialEnvVars` shall throw `PulumiCredentialsNotConfiguredError` instead of returning an empty environment. (observed)
- [x] **IAC-ENGINE-CRED-005**: `getOrCreateStack` shall place the backend URL, `AWS_REGION` and passphrase after the credential variables in the engine environment, so a credential source can never overwrite the backend variables. (observed)
- [x] **IAC-ENGINE-CRED-006**: The engine leaf shall log only the credential source kind and never an access key id, secret access key or session token, and decrypted key material shall stay in the main process and never cross IPC to the renderer. (OpenSpec: pulumi-engine-runtime / Wizard-selected credentials reach the engine)

## Output redaction

- [x] **IAC-ENGINE-REDACT-001**: While a preview or apply streams engine output, `PulumiService` shall replace every operator-set game-server environment value with a fixed placeholder before the line reaches the run record, the live stream or `pulumi.log`. (observed)
- [ ] **IAC-ENGINE-REDACT-002**: While a destroy streams engine output, `PulumiService` shall apply the same game-server environment-value redaction as preview and apply. (observed) (gap: destroy's `push` enqueues raw lines, `PulumiService.ts:3034-3037`)

## Stale backend lock recovery

- [x] **IAC-ENGINE-LOCK-001**: Immediately before every engine call that can take the DIY backend lock (`up`, `destroy`, and stack-init `refresh`), `PulumiService` shall record a lock-ownership attempt via `ElectronStoreService.recordPulumiLockAttempt`. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-002**: When an `up` or `destroy` settles in any way other than escalation, `PulumiService` shall clear its lock-ownership record; when it escalates, it shall keep the record as reclaim evidence. (observed)
- [x] **IAC-ENGINE-LOCK-003**: When an `up` or `destroy` hits a backend lock conflict, `classifyStackLockConflict` shall return `reclaimable-own-orphan` only if every parsed lock matches this host's OS username and hostname, names a PID confirmed dead by `ESRCH`, and is paired with a distinct fresh ownership record started at or before the lock. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-004**: When an `up` or `destroy` lock conflict is classified `reclaimable-own-orphan`, `PulumiService` shall clear it with `stack.cancel()` and retry the call once without prompting the operator. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-005**: If an `up` or `destroy` lock conflict cannot be proven to be this installation's orphan, then `PulumiService` shall throw `PulumiUnrecognizedLockError` naming the stack and each lock's holder (`user@host`, PID) and coarse age, and shall clear nothing until the operator confirms through the stale-lock clear flow. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-006**: If a lock's PID check fails with anything other than `ESRCH` (for example `EPERM`), then lock recovery shall treat the holder as possibly alive and require confirmation. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-007**: Lock recovery shall not treat the absence of an in-flight operation in this app instance as evidence that a lock is stale; a lock held by another installation shall never be auto-reclaimed. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [x] **IAC-ENGINE-LOCK-008**: When classifying a lock conflict, `classifyStackLockConflict` shall prune ownership records older than two hours, so a leaked record cannot arm auto-reclaim indefinitely. (observed)
- [x] **IAC-ENGINE-LOCK-009**: While a preview, apply, destroy or rollback is in flight in this app instance, a new plan, apply or destroy request shall be refused as busy through `getOperationInFlight()` and the controller's conflict response, with no lock recovery offered. (OpenSpec: pulumi-engine-runtime / Stale backend lock recovery)
- [ ] **IAC-ENGINE-LOCK-010**: When the stack-init `refresh` hits a backend lock conflict, `PulumiService.initializeStack` shall classify and reclaim or surface it exactly as `up` and `destroy` do. (observed) (gap: `refresh()` at `PulumiService.ts:1168` has no lock classification; a conflict becomes `PulumiStackInitializationError('operation')`)

## Engine process lifecycle

- [x] **IAC-ENGINE-LIFE-001**: When the abort signal of a preview, up or destroy fires, `runWithEscalatingCancellation` shall forward it to the SDK so a single `SIGINT` reaches the engine invocation. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle)
- [x] **IAC-ENGINE-LIFE-002**: If the abort signal is already aborted before a preview, up or destroy starts, then `runWithEscalatingCancellation` shall refuse to invoke it and reject with `PulumiOperationNotStartedError`. (observed)
- [x] **IAC-ENGINE-LIFE-003**: If a cancelled preview, up or destroy has not settled within `PULUMI_CANCELLATION_ESCALATION_TIMEOUT_MS` (30 s), then `runWithEscalatingCancellation` shall stop waiting and reject with `PulumiOperationEscalatedError`, sending no further signal. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle)
- [ ] **IAC-ENGINE-LIFE-004**: When escalation abandons an engine invocation, the escalation error message and log line shall say the invocation was abandoned, not that it was forcefully terminated. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle) (gap: "has been forcefully terminated" at `PulumiCancellation.ts:118-119`, "force-terminating" at `:232`)
- [x] **IAC-ENGINE-LIFE-005**: When an apply or destroy ends not-started, aborted or escalated, `PulumiService` shall record the run outcome as `aborted` with a null exit code and release the durable apply lock through `RunLockService.releaseRun`. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle)
- [ ] **IAC-ENGINE-LIFE-006**: When the operator cancels an in-flight plan, apply or destroy, the system shall abort that operation's signal so `SIGINT` reaches the engine. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle) (gap: no `iac.*.cancel` channel is registered; aborts fire only on `WebContents` destruction, `iac.controller.ts:532-549,740`)
- [ ] **IAC-ENGINE-LIFE-007**: `PulumiService.initializeStack` shall accept an abort signal and run its `refresh` through the same escalating-cancellation and leaked-promise wrappers as up and destroy. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle) (gap: `initializeStack(onPhase?)` takes no signal and `stack.refresh()` runs bare, `PulumiService.ts:1113,1168`)
- [x] **IAC-ENGINE-LIFE-008**: When a cancellable engine call settles, `runWithEscalatingCancellation` shall clear its escalation timer and remove its abort listener, so no engine-leaf listener keeps the event loop alive after an idle quit. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle)
- [ ] **IAC-ENGINE-LIFE-009**: When the app is quit while an infrastructure operation is running, the system shall abort the operation during shutdown and the process shall exit rather than hang. (OpenSpec: pulumi-engine-runtime / Engine process lifecycle) (gap: no `before-quit`/`will-quit` handler or Nest shutdown hook, `electron-entry.ts:251`)

## Leaked-promise recovery

- [x] **IAC-ENGINE-LEAK-001**: If a preview, up or destroy rejects only because the SDK reports promises still active after an otherwise successful run, then `runTreatingLeakedPromiseAsSuccess` shall treat it as success and return the result rebuilt by the caller from `stack.outputs()`/`stack.info()`. (observed)
- [x] **IAC-ENGINE-LEAK-002**: If a preview, up or destroy rejects for any reason other than the leaked-promise check, then `runTreatingLeakedPromiseAsSuccess` shall rethrow the original error unchanged. (observed)
- [x] **IAC-ENGINE-LEAK-003**: When `runTreatingLeakedPromiseAsSuccess` recovers a leaked-promise result, it shall log the leak error's `message` and `stack` rather than the raw error object. (observed)

## Stack initialization

- [x] **IAC-ENGINE-INIT-001**: When the wizard's final step calls `iac.stack.initialize`, `PulumiService.initializeStack` shall run the `engine`, `plugins` and `operation` phases in order (create or select the stack with an inert program, install the `@pulumi/aws` plugin at its installed package version, then `stack.refresh()`) and stream each phase's start and end. (OpenSpec: pulumi-engine-runtime / App-managed engine provisioning)
- [x] **IAC-ENGINE-INIT-002**: If `initializeStack` is called while a preview, apply, destroy or rollback is in flight, then it shall throw `PulumiOperationInFlightError`; if another stack initialization is in flight, then it shall throw a plain `Error` refusing the second call. (observed)
- [x] **IAC-ENGINE-INIT-003**: If `initializeStack` runs before the state bucket or AWS region is configured, then it shall throw `PulumiStackInitializationError('engine')` directing the operator to the bootstrap step. (observed)
- [x] **IAC-ENGINE-INIT-004**: If `initializeStack` fails, then it shall throw `PulumiStackInitializationError` tagged with the phase it attributes the failure to: `engine` for credential, pasted-credential decrypt and engine provisioning errors, `plugins` for the plugin install, and `operation` otherwise. (observed)
- [ ] **IAC-ENGINE-INIT-005**: If `getOrCreateStack` fails inside `initializeStack` after the engine phase has ended (STS, legacy migration or `createOrSelect`), then the failure shall be attributed to a phase the wizard can mark accurately rather than leaving the wizard to mark the finished `engine` row as failed. (observed) (gap: classified `operation` before any `operation` start event, `PulumiService.ts:1346-1354`; wizard blames last-started row, `stack-init-step.component.tsx:129,140,149`) [inferred]
- [x] **IAC-ENGINE-INIT-006**: The wizard's `StackInitializationStep` shall render one checklist row per stack-init phase, mark a row in-progress on its start event and done on its end event, and on a stream error mark the last-started row failed, show the error message, and offer retry. (observed)
- [x] **IAC-ENGINE-INIT-007**: The wizard's `StackInitializationStep` shall debounce its `iac.stack.initialize` call with a zero-delay timer cleared on unmount, so a React StrictMode double mount starts exactly one stack initialization. (observed)
