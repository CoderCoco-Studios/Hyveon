# IaC Infrastructure Program Specs

EARS requirements for prefix `IAC-PROGRAM`, the leaf described in `docs/intent/iac/program/program-design.md`.

## Workspace and Packaging

- [x] **IAC-PROGRAM-WS-001**: The infrastructure definition shall live in the `@hyveon/infra` npm workspace as TypeScript, exported through `createInfraProgram` from `app/packages/infra/src/index.ts` (`index.ts`, `program.ts:556`). (OpenSpec: pulumi-infra-program / Infrastructure program workspace)
- [x] **IAC-PROGRAM-WS-002**: When the desktop app is packaged, the infrastructure program shall be carried as a dependency of `@hyveon/desktop-main` inside the application bundle, so a preview needs no infrastructure source files outside the bundle (`desktop-main/package.json:26`, `PulumiService.ts:19`). (OpenSpec: pulumi-infra-program / Infrastructure program workspace)
- [x] **IAC-PROGRAM-WS-003**: When `npm run app:lint` and `npm run app:test` run from the repo root, both shall include the `@hyveon/infra` workspace (`app/eslint.config.js` lints `app/`; `app/vitest.config.ts:61-62` collects `packages/**/*.test.ts`). (OpenSpec: pulumi-infra-program / Infrastructure program workspace)
- [x] **IAC-PROGRAM-WS-004**: The infrastructure program shall be an inline Pulumi Automation API `PulumiFn` closure whose body is `defineAll` followed by `buildStackOutputs`, declaring every resource inside the closure and none at module scope (`program.ts:556-561`). (observed)
- [x] **IAC-PROGRAM-WS-005**: The infrastructure program shall take the Lambda bundle directory as a required machine-local `lambdaBundlesDir` option outside `DeploymentConfig`, with no default anywhere in `@hyveon/infra` (`program.ts:42-63`, `lambdas.ts:16-29`). (observed)
- [ ] **IAC-PROGRAM-WS-006**: The `@hyveon/infra` build output shall exclude test-only helpers under `src/testing/` (gap: `infra/tsconfig.json` excludes only `src/**/*.test.ts`, so `testing/fixtures.ts` and `testing/pulumiMocks.ts` compile into `dist/`). (observed)

(OpenSpec: pulumi-infra-program / Typed game-server configuration model)
- [x] **IAC-PROGRAM-FANOUT-002**: When an entry is added to `DeploymentConfig.gameServers`, a preview of the infrastructure program shall report that game's full per-game resource set with no source edit (`ecs.ts:184-347`, `efs.ts:116-161`). (OpenSpec: pulumi-infra-program / Typed game-server configuration model)
- [x] **IAC-PROGRAM-FANOUT-003**: When an entry is removed from `DeploymentConfig.gameServers`, a preview of the infrastructure program shall report deletion of exactly that game's per-game resources, because each is keyed by the game name (`ecs.ts:187`, `ecs.ts:336`, `efs.ts:119`). (OpenSpec: pulumi-infra-program / Typed game-server configuration model)
- [x] **IAC-PROGRAM-FANOUT-004**: The infrastructure program and the desktop app shall consume the same `DeploymentConfig` and `GameServerConfig` types imported from `@hyveon/shared`, so a shape change fails type-checking in both (`program.ts:21`). (OpenSpec: pulumi-infra-program / Typed game-server configuration model)

(observed)
- [x] **IAC-PROGRAM-SG-002**: Where at least one game port is declared `visibility: 'internal'`, the game-servers security group shall scope that port's ingress to the VPC CIDR block and shall look the CIDR up only in that case (`securityGroups.ts:258-264`). (observed)
- [x] **IAC-PROGRAM-SG-003**: If a game port carries an unrecognised `visibility` value, then the game-servers security group shall grant it no ingress at all (`securityGroups.ts:141-143`, `securityGroups.ts:162-164`). (observed)
- [x] **IAC-PROGRAM-SG-004**: When a game port declares protocol `icmp`, the game-servers security group shall represent it as an ICMP rule with `fromPort` set to the ICMP type and `toPort: -1` (`securityGroups.ts:221-222`). (observed)
- [x] **IAC-PROGRAM-SG-005**: When at least one game has `https: true`, the game-servers security group shall allow `0.0.0.0/0` ingress on 443/tcp and 80/tcp (`securityGroups.ts:269-279`). (OpenSpec: in-task-tls-termination / Security-group ingress for HTTPS games)
- [x] **IAC-PROGRAM-SG-006**: When no game has `https: true`, the game-servers security group shall contain no 443/tcp or 80/tcp ingress (`securityGroups.ts:269`, `securityGroups.ts:197-199`). (OpenSpec: in-task-tls-termination / Security-group ingress for HTTPS games)
- [x] **IAC-PROGRAM-SG-007**: The game-servers security group shall not grant ingress on an HTTPS game's `webPort` over tcp, because `ingressPorts` drops a tcp entry equal to `webPort` (`shared/src/gameServerPorts.ts:101-107`, `securityGroups.ts:171`). (OpenSpec: in-task-tls-termination / Security-group ingress for HTTPS games)
- [x] **IAC-PROGRAM-SG-008**: When an HTTPS game declares additional `ports` entries, the game-servers security group shall ingress them like any other game's ports, honouring each entry's `visibility` (`securityGroups.ts:166-184`). (OpenSpec: in-task-tls-termination / Security-group ingress for HTTPS games)
- [x] **IAC-PROGRAM-SG-009**: The game-servers, file-manager and EFS security groups shall carry open egress, and the file-manager group shall declare an explicit empty ingress list so an apply revokes any legacy rule (`securityGroups.ts:316-348`). (observed)
- [x] **IAC-PROGRAM-SG-010**: The EFS security group shall allow NFS 2049/tcp ingress from the game-servers and file-manager groups, and additionally from the efs-seeder group where one exists (`securityGroups.ts:377-406`). (observed)
- [x] **IAC-PROGRAM-SG-011**: Where at least one game declares `file_seeds`, the infrastructure program shall declare an efs-seeder security group with no in-line egress and a standalone egress rule allowing only NFS 2049/tcp to the EFS group (`securityGroups.ts:356-372`, `securityGroups.ts:410-422`). (observed)
- [x] **IAC-PROGRAM-SG-012**: Where at least one game declares a `healthCheck`, the infrastructure program shall declare a health-check security group with one standalone egress rule per distinct health-check port to the game-servers group, and the game-servers group shall admit each such port only from the health-check group (`securityGroups.ts:286-314`, `securityGroups.ts:430-446`). (observed)
- [x] **IAC-PROGRAM-SG-013**: Each infrastructure-program security group shall declare its rules either all in-line or all as standalone `SecurityGroupRule` resources, never both (`securityGroups.ts:19-38`). (observed)

## Dropped from OpenSpec

- `pulumi-infra-program / Configuration persisted as versioned JSON` (all four scenarios): owned by the `deployment-config` leaf, not this program.
- `pulumi-infra-program / No secret material enters the stack`, the sentence that the secrets provider "is machine-bound and has no recovery path": contradicts `pulumi-engine-runtime` and the code (portable passphrase); owned by `iac/engine`.
- `pulumi-infra-program / Resource parity with the retired Terraform module`, parity with the Terraform module as such: the Terraform module is retired, so the requirement is restated as the concrete invariants in ECS-002, DNS-001, IAM-005 and LAMBDA-002 rather than as parity.
- `in-task-tls-termination / No load-balancer or ACM resources`, the literal "no ACM certificate" for this stack: the single stack also declares the Discord-domain ACM certificate (`discordDomain.ts:117-150`); restated with an explicit scope as TLS-009.
- `in-task-tls-termination / No load-balancer or ACM resources`, "after the removal apply ... no orphaned ELB or ACM resources": a one-time migration check, not a standing behaviour.
- `in-task-tls-termination / HTTPS served with automatically-issued certificates`, "valid HTTPS within approximately 2 minutes": a runtime latency observation of Caddy and DNS propagation with no implementing code in this leaf.
- `in-task-tls-termination / HTTPS games use the Lambda-managed DNS lifecycle`, the UPSERT-on-RUNNING / DELETE-on-STOPPED handler behaviour and "no ELBv2 API calls" in Lambda sources: owned by `game-runtime/task-and-dns`; only the trigger and env wiring are kept here (LAMBDA-006, LAMBDA-007).
- `lambda-runtime-currency / Bundle target matches the executing runtime`, scenario "any `esbuild.config.mjs` ... `target`": the target lives once in `buildLambda.mjs`, restated as RUNTIME-004.
- `lambda-runtime-currency / Bundle target matches the executing runtime`, scenario "either side changed alone MUST NOT be merged": a review-process rule, not a behaviour of the program.
- `lambda-runtime-currency / Runtime-provided SDK is treated as a dependency`, scenario "each Lambda's SDK calls are exercised against the deployed functions before the change is complete": a change-verification process, not a behaviour of the program.
- `lambda-runtime-currency / Lambdas run a supported AWS runtime`, the listing of `efs-seeder` among "always-provisioned functions": the code provisions it per game only for games with `file_seeds` (`iam.ts:371-378`, `lambdas.ts:715`); restated as LAMBDA-001 and RUNTIME-003.
