# Helper Task Specs

EARS requirements for prefix `HELPER`; design in `docs/intent/helper-task/helper-task-design.md`. Verified against `5c55a380`.

## Folder selection

- [x] **HELPER-SELECT-001**: When the operator chooses "Choose folder" in the add-game wizard's Storage step or on the game detail page's upload card, the desktop main process shall open the native directory dialog and scan the chosen folder, returning only tree metadata and a `scanId` to the renderer. (OpenSpec: game-volume-folder-upload / Operator selects a local folder and which entries to include)
- [x] **HELPER-SELECT-002**: When a folder-upload scan completes, the folder-seed section shall present the folder as a tree in which every directory and file has its own include checkbox, with every entry included by default. (OpenSpec: game-volume-folder-upload / Operator selects a local folder and which entries to include)
- [x] **HELPER-SELECT-003**: When the operator deselects a directory in the folder-upload include tree, the folder-upload plan shall exclude every file beneath that directory. (OpenSpec: game-volume-folder-upload / Operator selects a local folder and which entries to include)
- [x] **HELPER-SELECT-004**: When a folder upload runs with some top-level entries of the chosen folder deselected, the system shall upload only files under the included entries, each to the destination directory joined with its path relative to the chosen folder. (OpenSpec: game-volume-folder-upload / Operator selects a local folder and which entries to include)
- [x] **HELPER-SELECT-005**: If the folder-upload destination is not a clean absolute path equal to or beneath one of the game's volume `container_path`s, then the folder-seed section shall show a validation error, shall not persist the selection, and the upload card shall not enable the upload action. (OpenSpec: game-volume-folder-upload / Operator selects a local folder and which entries to include)
- [x] **HELPER-SELECT-006**: When the folder-upload destination lies beneath more than one of the game's volumes, destination validation shall resolve it to the volume with the deepest matching `container_path`. (observed)
- [x] **HELPER-SELECT-007**: The folder scan service shall hold at most 8 scans by `scanId`, and if an upload request names a scan that is no longer held, then the folder-upload start guard shall refuse with "The folder scan has expired; pick the folder again." (observed)

## Upload into the volume

- [x] **HELPER-UPLOAD-001**: When the operator starts a folder upload for a deployed game with no helper session open, the system shall launch a helper session for the run, write the planned files at their destinations through the helper's REST API, and stop the helper when the run releases the session as its last holder. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-002**: When a folder upload's destination lies under a game volume other than the first, the system shall write the files into the volume that owns the destination and write nothing to any other volume. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-003**: The folder-upload flow shall keep file contents and the helper credential in the desktop main process and shall not send them to the renderer, write them to `deployment-config.json`, or log them. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-004**: While a game's infrastructure has not been applied, the folder-upload card shall disable the upload action with the explanation that the infrastructure must be applied first and that the selection is kept. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-005**: If a folder upload is requested while the stack outputs are unavailable, then the desktop main process shall refuse the upload with a "not deployed yet ... your selection is kept" message. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-006**: While the game's server task is running or starting, the folder-upload card shall disable the upload action with an explanation that the server must be stopped first, and the desktop main process shall refuse an upload request for that game. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-008**: If the check for a running game server task fails during the folder-upload start guard, then the system shall refuse the upload with an explanation that it could not confirm the server is stopped, and write nothing. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-009**: If a folder upload's destination belongs to a volume whose access point the last infrastructure apply has not exported, then the system shall refuse the upload before launching any helper, explain that the infrastructure must be applied, and keep the selection. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-010**: While the application holds a browse session for a game, a folder upload for that game shall use that session's helper, and the helper shall keep running after the upload ends for as long as the browse page holds it. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-011**: If a file-manager helper is running for a game but the application holds no session for it, then a folder upload for that game shall be refused with a message asking the operator to restart the session rather than use that helper. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [x] **HELPER-UPLOAD-012**: While a folder upload is starting or running for a game, the desktop main process shall refuse a second upload request for the same game. (observed)
- [ ] **HELPER-UPLOAD-013**: When the operator cancels a folder upload while its start guards are still running, the system shall prevent the run from starting. (observed) (gap: `cancel()` consults only `active`, `FolderUploadService.ts:183-187`, so a game still in `preparing`, `:220-244`, starts anyway)
- [x] **HELPER-UPLOAD-014**: When a folder upload launches a helper session, the session registry shall poll for the helper's public IP every 3 s for up to 3 minutes, and if the helper task stops first, then the run shall fail with ECS's stop reason. (observed)
- [x] **HELPER-UPLOAD-015**: When a launching helper has a public IP, the session registry shall retry FileBrowser login over the pinned connection for up to 2 minutes before failing the session. (observed)
- [x] **HELPER-UPLOAD-016**: If a folder-upload run or session launch fails after its helper task died, then the failure message shall append the helper's ECS stop reason unless the message already reports that the helper stopped before it was reachable. (observed)
- [x] **HELPER-UPLOAD-017**: If the stack outputs carry no per-volume access points for the game (a stack applied by an older build), then the system shall refuse every folder upload for that game, including one into its first volume, before launching any helper, and keep the selection. (OpenSpec: game-volume-folder-upload / Upload goes directly into the mounted volume)
- [ ] **HELPER-UPLOAD-018**: While a folder-upload run is writing, if the game's server task starts or its state can no longer be confirmed, then the run shall stop writing before the next file. (observed) (gap: the server is checked once in preflight, `FolderUploadService.ts:290-297`, and never again during `uploadAll`, `:367`; the in-app `games.start` refusal does not cover the preflight window or Discord `/server-start`, see HELPER-FB-042)
- [x] **HELPER-UPLOAD-019**: If the session registry retries a folder-upload write after an operator-IP recovery, then the write shall fail as `unreachable` instead of replaying the consumed stream, leaving the retry to the upload engine. (observed)
- [x] **HELPER-UPLOAD-020**: When a folder-upload run starts, it shall map its plan onto the live session's volume layout, and if that session does not mount the destination volume or uses the legacy fallback layout, then the run shall fail before writing, asking the operator to stop and start the session. (observed)

## Upload helper reach and transport

- [x] **HELPER-REACH-001**: When a file-manager helper is launched, the system shall add an ingress rule to the file-manager security group for only the operator's detected public IPv4 as a `/32` on port 8080, and the group shall declare no other ingress. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [x] **HELPER-REACH-002**: Every file-manager helper shall require the per-launch credential, held only as a bcrypt hash in the task definition. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [x] **HELPER-REACH-003**: When any file-manager helper is launched, for browsing or uploading, the system shall generate a self-signed P-256 certificate for that launch and serve FileBrowser over HTTPS with it. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [x] **HELPER-REACH-004**: If a helper endpoint presents a certificate whose SHA-256 fingerprint differs from the one generated for the launch, then the FileBrowser client shall abort the connection without sending the credential or any file content, and shall not retry. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [x] **HELPER-REACH-005**: When a file-manager helper stops through stop, the last holder releasing, a failed session, the browse grace timer or a sweep, the system shall revoke each operator-IP ingress rule that no remaining helper's `OperatorIp` tag needs. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [x] **HELPER-REACH-006**: If the operator's public IP changes during a folder upload and the session's one re-authorization retry cannot recover the connection, then the run shall be reported failed with a Resume action that re-detects the IP and re-authorizes. (OpenSpec: game-volume-folder-upload / Only the operator can reach the upload helper)
- [ ] **HELPER-REACH-007**: If a file-manager helper launch fails after the operator-IP ingress rule was added, including during certificate generation or task-definition registration, then the system shall revoke that rule before returning the failure. (observed) (gap: `generateEphemeralCert` and `registerTaskDefinition` run outside any try after `authorizeIngress`, `FileManagerService.ts:374,393,403`)
- [x] **HELPER-REACH-008**: If any remaining file-manager helper lacks an `OperatorIp` tag, or the helper listing fails, then the system shall revoke no operator-IP ingress rules. (observed)

## Helper launch and lifetime

- [x] **HELPER-LAUNCH-001**: When a file-manager helper is launched, the system shall register a fresh `filebrowser-{game}` Fargate task definition and start it with `RunTask`, and when that helper is stopped, the system shall deregister the definition; no ECS Service shall be used. (observed)
- [x] **HELPER-LAUNCH-002**: If a file-manager helper with `startedBy: filemgr-{game}` already exists, then a new helper launch for that game shall be refused with code `helper-open`, and the session registry shall report the session as `orphaned`. (observed)
- [x] **HELPER-LAUNCH-003**: If the stack outputs provide no access point for any of the game's volumes, or lack the file-manager security group, then a helper launch shall return a modeled failure without calling `RunTask`. (observed)
- [x] **HELPER-LAUNCH-004**: When a file-manager helper is launched, the system shall create a one-time EventBridge Scheduler schedule `filemgr-stop-{game}` that stops the task after 2 hours, and when the helper is stopped, the system shall delete that schedule, treating a missing schedule as success. (observed)
- [ ] **HELPER-LAUNCH-005**: If a helper session's auto-stop schedule cannot be created, because the scheduler role output is missing or the schedule call fails, then a folder-upload run using that session shall surface that failure rather than run without the auto-stop backstop. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up) (gap: `launchHelper` returns `scheduleWarning`, `FileManagerService.ts:487,498-514`, and `HelperSessionRegistry.launch` never reads it, `HelperSessionRegistry.ts:435-443`)
- [ ] **HELPER-LAUNCH-006**: When a browse session's auto-stop schedule cannot be created, the file browser page shall warn the operator to stop the session manually. (observed) (gap: regression; `scheduleWarning` has no consumer at all, `HelperSessionRegistry.ts:435-443`, and `HelperSessionSnapshot` has no field for it, `:26-37`)
- [x] **HELPER-LAUNCH-007**: Every helper task definition shall reference the FileBrowser image by an immutable digest and exact version tag. (OpenSpec: game-volume-file-browser / Replaceable file backend)
- [x] **HELPER-LAUNCH-008**: When a file-manager helper is launched, the system shall make a best-effort write of the credential's bcrypt hash to the FileBrowser credential secret, logging and continuing on failure. (observed)

## Helper tagging and stray cleanup

- [x] **HELPER-STRAY-001**: When a folder upload launches a helper, the system shall tag its task `Purpose=seed-upload` and `Project=hyveon` in addition to `OperatorIp`. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)
- [x] **HELPER-STRAY-002**: When a folder-upload run completes, fails or is cancelled, the run shall release its session hold, starting the helper's teardown when it was the last holder, before publishing the terminal phase. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)
- [x] **HELPER-STRAY-003**: When the desktop app starts under Electron, the folder-upload service shall stop every file-manager helper older than 15 minutes, best-effort, and the game's last-run state shall remain resumable. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)
- [x] **HELPER-STRAY-004**: When the operator runs "Clean up stray helpers" from Diagnostics, the system shall stop every file-manager helper task, of any age, that neither an active upload run nor an application-held session owns, and report the stopped tasks and per-task errors. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)
- [x] **HELPER-STRAY-005**: When the stray-helper cleanup runs while the application holds a browse session, the cleanup shall not stop that session's helper. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)
- [x] **HELPER-STRAY-006**: When a folder upload completes, fails or is cancelled, the upload shall release its hold on the game's helper session, and the system shall stop the helper only when nothing else holds the session. (OpenSpec: game-volume-folder-upload / Helper sessions are tagged and stray ones are cleaned up)

## Progress meter

- [x] **HELPER-PROG-001**: While a folder upload runs, the game detail page's progress meter shall show percent complete, bytes done of total, files done of total, the current file, transfer rate and estimated time remaining. (OpenSpec: game-volume-folder-upload / Live progress meter)
- [x] **HELPER-PROG-002**: While a folder upload runs, the desktop main process shall push a progress snapshot to every window on `folderUpload.progress` at least every 500 ms. (OpenSpec: game-volume-folder-upload / Live progress meter)
- [x] **HELPER-PROG-003**: While a single file of a folder upload is streaming, the progress byte count shall advance with the streamed bytes rather than only when the file completes, and shall roll back a failed attempt's bytes. (OpenSpec: game-volume-folder-upload / Live progress meter)
- [x] **HELPER-PROG-004**: The folder-upload progress meter shall label the phases starting helper, awaiting confirmation, uploading, verifying, done, failed and cancelled, and shall show 100% only in the done phase. (OpenSpec: game-volume-folder-upload / Live progress meter)
- [x] **HELPER-PROG-005**: When the operator cancels a running folder upload from the progress meter, the system shall stop uploading, release the run's session hold (stopping the helper unless another holder keeps it), and show a cancelled state with a Resume action. (OpenSpec: game-volume-folder-upload / Live progress meter)
- [x] **HELPER-PROG-006**: When no folder-upload run exists in this session for a game but a last run is stored, the progress meter shall show that last run's outcome with a Resume action. (observed)

## Resume and failure handling

- [x] **HELPER-RESUME-001**: When a folder upload is retried, the upload engine shall skip each planned file already present on the volume at its expected size and count it as done. (OpenSpec: game-volume-folder-upload / Resume and failure handling)
- [x] **HELPER-RESUME-002**: When a folder upload is retried, the upload engine shall overwrite a planned file present on the volume at a different size, including one left partially written by an interrupted run. (OpenSpec: game-volume-folder-upload / Resume and failure handling)
- [x] **HELPER-RESUME-003**: When a folder-upload file transfer fails transiently, the upload engine shall retry it up to 3 attempts with a 500 ms times attempt backoff, and shall not retry cancellation, a changed local file, a pin, auth, not-found or conflict failure, or 4xx responses other than 408 and 429. (OpenSpec: game-volume-folder-upload / Resume and failure handling)
- [x] **HELPER-RESUME-004**: If a folder-upload file exhausts its attempts, then the run shall fail, abort the remaining transfers, and report the failing path and error. (OpenSpec: game-volume-folder-upload / Resume and failure handling)
- [x] **HELPER-RESUME-005**: If the helper's auto-stop elapses mid-upload, then the run shall be reported failed with a Resume action that launches a fresh helper and continues. (OpenSpec: game-volume-folder-upload / Resume and failure handling)
- [x] **HELPER-RESUME-006**: If a local file's size or mtime differs from the scan before an upload attempt, then the upload engine shall fail that file permanently. (observed)
- [x] **HELPER-RESUME-007**: The folder-upload engine shall transfer files through a pool of 4 concurrent uploads. (observed)

## Verification

- [x] **HELPER-VERIFY-001**: When a folder upload finishes transferring, the system shall list every planned parent directory on the volume and compare per-file presence and size against the plan. (OpenSpec: game-volume-folder-upload / Verification after upload)
- [x] **HELPER-VERIFY-002**: When folder-upload verification finds every planned file at its size, the run shall be reported done with the file count and total bytes. (OpenSpec: game-volume-folder-upload / Verification after upload)
- [x] **HELPER-VERIFY-003**: If folder-upload verification finds missing or size-mismatched files, then the run shall fail with a message naming at most 5 of those paths plus a count of the rest, and the progress meter shall offer Retry. (OpenSpec: game-volume-folder-upload / Verification after upload)

## Overwrite warning

- [x] **HELPER-OVER-001**: After the helper session is connected and before any directory is created or file written, the folder-upload run shall list the destination directories the plan touches and classify each planned file as new, identical (same size) or conflicting (different size). (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-002**: When a folder-upload plan has at least one conflict, the run shall enter `awaiting-confirmation` with the helper still running, show the conflict, identical and new counts with up to 20 sample conflicting paths and their existing and new sizes, and write nothing until the operator confirms. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-003**: When the operator chooses "Overwrite and upload" in the folder-upload overwrite warning, the run shall continue, replacing conflicting files and skipping identical ones. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-004**: When the operator declines the folder-upload overwrite warning, the run shall end as cancelled with nothing written and its session hold released, so a helper nothing else holds is stopped and its operator-IP rule revoked. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-005**: If the folder-upload overwrite warning is unanswered for 10 minutes, then the run shall be cancelled with a timeout message and its session hold released. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-006**: When every planned file of a folder upload is new or identical, the run shall start uploading without a prompt. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-007**: When the previous folder-upload run for the same folder, include set and destination failed or was cancelled after copying files, and the conflicts do not exceed the engine's concurrency, the run shall treat those conflicts as its own partial files and not prompt. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)
- [x] **HELPER-OVER-008**: The folder-upload overwrite classification shall count existing volume files the plan does not include only as context and never as conflicts. (OpenSpec: game-volume-folder-upload / Warn before overwriting existing volume files)

## Safety limits and state

- [x] **HELPER-SAFE-001**: When the folder scan meets a symbolic link, it shall omit the link and count it, and the folder-seed section shall state how many links will be skipped. (OpenSpec: game-volume-folder-upload / Safety limits and scope of state)
- [x] **HELPER-SAFE-002**: If a planned folder-upload file's remote path would contain `..`, `.`, backslash, NUL or an absolute segment, or fall outside the destination's volume, then the system shall reject it. (OpenSpec: game-volume-folder-upload / Safety limits and scope of state)
- [x] **HELPER-SAFE-003**: The system shall persist each game's folder selection (`localPath`, `include`, `destination`) and last-run state in electron-store under `folderUpload`, and not in `deployment-config.json`. (OpenSpec: game-volume-folder-upload / Safety limits and scope of state)
- [x] **HELPER-SAFE-004**: When the operator reopens the app after selecting a folder for a game, the game's upload card shall restore the selection by re-scanning the stored `localPath` and shall show the last-upload status. (OpenSpec: game-volume-folder-upload / Safety limits and scope of state)
- [x] **HELPER-SAFE-005**: The folder-upload feature shall leave a game's inline `file_seeds` and the efs-seeder path unchanged. (OpenSpec: game-volume-folder-upload / Safety limits and scope of state)
- [x] **HELPER-SAFE-006**: When a folder upload is started from the file browser page, the run shall neither replace the game's saved folder-upload selection nor record its outcome as the selection's last run, and shall not treat existing files as its own partial uploads. (observed)

## Deploy-time seeding

- [x] **HELPER-SEED-001**: Where a game declares `file_seeds`, the infra program shall provision a per-game efs-seeder Lambda mounted on the game's first volume access point at `/mnt/efs` and invoke it synchronously during apply, re-invoking only when the seeds change. (observed)
