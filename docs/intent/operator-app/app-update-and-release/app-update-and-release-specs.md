# App Update and Release Specs

EARS requirements for prefix `APP-UPDATE`; design in [app-update-and-release-design.md](./app-update-and-release-design.md).

## Boot-time update check

- [x] **APP-UPDATE-BOOT-001**: When the desktop-main updater's `initUpdater` runs outside a real Electron main process (`process.versions.electron` undefined), the updater shall return without importing `electron-updater` or making any network request. (OpenSpec: auto-update-scaffold / Updater is wired but inert by default)
- [x] **APP-UPDATE-BOOT-002**: When the packaged app boots and the `enableAutoUpdate` electron-store flag is unset or `false`, `initUpdater` shall log a single "update checks disabled" line and return without importing `electron-updater` or calling `checkForUpdates`. (OpenSpec: auto-update-scaffold / Updater is wired but inert by default)
- [x] **APP-UPDATE-BOOT-003**: When the packaged app boots and `enableAutoUpdate` is `true`, `initUpdater` shall run one update check against the GitHub Releases feed (with the feed fallback of APP-UPDATE-FALL-001) and log `error`, `update-available`, `update-not-available` and `update-downloaded` events through the main-process logger. (OpenSpec: auto-update-scaffold / Updater is wired but inert by default)
- [x] **APP-UPDATE-BOOT-004**: While `enableAutoUpdate` is `false`, the updater shall perform no update-feed or GitHub releases API request that the operator did not initiate from the Settings page, and shall emit no update-check events beyond the single boot-time disabled log line. (OpenSpec: auto-update-scaffold / Update-check telemetry is gated by the same flag, narrowed; see Dropped)
- [x] **APP-UPDATE-BOOT-005**: If the boot-time update check rejects, then `initUpdater` shall swallow the rejection after its `error` listener has logged it, so no unhandled rejection reaches the Electron main process. (observed)
- [x] **APP-UPDATE-BOOT-006**: Every time desktop-main loads `electron-updater` (boot-time check, manual check, download or install), the updater shall set `autoDownload` and `autoInstallOnAppQuit` to `false` before use. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)

## enableAutoUpdate flag

- [x] **APP-UPDATE-FLAG-001**: The electron-store `AppStoreSchema` shall declare an optional boolean `enableAutoUpdate`, readable and writable through `ElectronStoreService`'s typed `get`/`set` in both the real electron-store backing and the in-memory backing used outside Electron. (OpenSpec: auto-update-scaffold / enableAutoUpdate flag lives in the typed electron-store schema)
- [x] **APP-UPDATE-FLAG-002**: When `enableAutoUpdate` has never been persisted, both the boot-time updater and the `iac.settings.autoUpdate.get` channel shall treat it as `false`. (OpenSpec: auto-update-scaffold / enableAutoUpdate flag lives in the typed electron-store schema)
- [x] **APP-UPDATE-FLAG-003**: When the renderer invokes `iac.settings.autoUpdate.get`, desktop-main shall return `{ ok: true, enableAutoUpdate, appVersion }`, with `appVersion` set to the running app version or `'unknown'` outside Electron. (OpenSpec: auto-update-scaffold / enableAutoUpdate flag lives in the typed electron-store schema)
- [x] **APP-UPDATE-FLAG-004**: If reading `enableAutoUpdate` from the store throws during `iac.settings.autoUpdate.get`, then desktop-main shall log the error and return `{ ok: false, code: 'error', message }` without rethrowing. (observed)
- [x] **APP-UPDATE-FLAG-005**: When the renderer invokes `iac.settings.autoUpdate.update` with a boolean `enableAutoUpdate`, desktop-main shall persist it via `ElectronStoreService` and return `{ ok: true, enableAutoUpdate }` echoing the value now in effect. (OpenSpec: auto-update-scaffold / enableAutoUpdate flag lives in the typed electron-store schema)
- [x] **APP-UPDATE-FLAG-006**: If `iac.settings.autoUpdate.update` receives a non-boolean `enableAutoUpdate`, no settings store is available, or the store write throws, then desktop-main shall return `{ ok: false, code: 'error', message }` and leave the stored value unchanged. (observed)
- [x] **APP-UPDATE-FLAG-007**: When `enableAutoUpdate` is changed while the app is running, desktop-main shall not trigger an update check; the new value shall take effect only at the next app start. (OpenSpec: auto-update-scaffold / enableAutoUpdate flag lives in the typed electron-store schema)

## Manual update check

- [x] **APP-UPDATE-CHECK-001**: When the operator triggers a manual update check, desktop-main shall run the check regardless of the `enableAutoUpdate` flag's value. (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-CHECK-002**: When a manual update check finds the running version current, desktop-main shall return `{ ok: true, updateAvailable: false }` and shall not download or install anything. (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-CHECK-003**: When a manual update check finds a newer version, desktop-main shall return `{ ok: true, updateAvailable: true, version }` and shall not download or install anything. (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-CHECK-004**: If a manual update check fails after the feed fallback, then desktop-main shall log the failure and return `{ ok: false, message }` without letting an exception escape to the IPC caller. (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-CHECK-005**: When a manual update check is requested outside a real Electron main process, desktop-main shall return `{ ok: false }` with an "only available in the packaged app" message without importing `electron-updater` or making any network call. (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-CHECK-006**: If `checkForUpdates` resolves `null` during a manual check (updater disabled for this build), then desktop-main shall return `{ ok: false }` with an "Update checks are disabled for this build." message. (observed)
- [x] **APP-UPDATE-CHECK-007**: When a manual update check settles, desktop-main shall remove every listener the check attached to the `autoUpdater` singleton. (observed)

## Update feed fallback

- [x] **APP-UPDATE-FALL-001**: If a boot-time, manual or pre-download update check's `checkForUpdates` call rejects, then the updater shall look up the newest GitHub release that is neither a draft nor a prerelease and carries the current platform's feed file (`latest.yml` on win32, `latest-mac.yml` on darwin, `latest-linux.yml` on linux), point the generic provider at that release's download URL, and retry the check exactly once. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [x] **APP-UPDATE-FALL-002**: When choosing the update-feed fallback release, the updater shall pick the eligible release with the greatest `published_at`, treating a missing or unparseable `published_at` as oldest and keeping the earlier entry on ties. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [x] **APP-UPDATE-FALL-003**: If no eligible fallback release exists, the releases lookup returns non-2xx or a non-array body, the lookup throws or exceeds its 10 s timeout, or the fallback retry fails, then the updater shall surface the original primary check error. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [x] **APP-UPDATE-FALL-004**: After an update-feed fallback retry succeeds or fails, the updater shall restore the primary `github` feed (`CoderCoco-Studios/Hyveon`) on the `autoUpdater` singleton. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [x] **APP-UPDATE-FALL-005**: The update-feed fallback shall never download or install an update. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [x] **APP-UPDATE-FALL-006**: When a manual check's primary attempt emits an `error` event and the fallback retry then succeeds, desktop-main shall resolve the manual check with the retry's availability result, not with the primary error. (OpenSpec: auto-update-scaffold / Failed update checks fall back to the newest release with a feed)
- [ ] **APP-UPDATE-FALL-007**: When looking up an update-feed fallback release, the updater shall consider every published release rather than only the newest page, so an eligible older release is found even when the most recent releases all lack the platform feed file. (observed) (gap: `app/packages/desktop-main/src/updater-fallback.ts:10` fetches `per_page=10` with no pagination)

## Download and install

- [x] **APP-UPDATE-DL-001**: The desktop app shall download or install an update only through the operator-initiated `iac.settings.autoUpdate.download` and `iac.settings.autoUpdate.install` actions; the boot-time check and the manual check shall remain detect-only. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-DL-002**: While an operator-initiated update download is in progress, desktop-main shall forward every `download-progress` event as `{ percent, transferred, total, bytesPerSecond }`. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-DL-003**: When an operator-initiated update download completes, desktop-main shall return `{ ok: true, version }` with the version reported by `update-downloaded`, without restarting the app. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-DL-004**: If an operator-initiated update download is requested while `electron-updater` has no cached check result in this process, then desktop-main shall re-run the update check (with fallback) once and retry the download before reporting failure. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [ ] **APP-UPDATE-DL-005**: When deciding whether an operator-initiated download lacks a cached check result, desktop-main shall detect that condition from updater state rather than from `electron-updater`'s rejection message text. (observed) (gap: `app/packages/desktop-main/src/updater.ts:172`, `:217` compare against the literal `'Please check update first'`)
- [x] **APP-UPDATE-DL-006**: If an operator-initiated update download fails, then desktop-main shall log the failure and return `{ ok: false, message }`, and shall remove its `download-progress`, `update-downloaded` and `error` listeners whether the download succeeded or failed. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-DL-007**: When an operator-initiated update download or install is requested outside a real Electron main process, desktop-main shall return `{ ok: false }` with an "only available in the packaged app" message without touching `electron-updater`. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-DL-008**: When the operator requests install of a downloaded update, desktop-main shall call `quitAndInstall(false, true)` so the app quits, runs the installer and relaunches, and shall return `{ ok: true }`. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [ ] **APP-UPDATE-DL-009**: If the operator requests install when no update has been downloaded in this process, then desktop-main shall return `{ ok: false, message }` instead of calling `quitAndInstall`. (observed: promised by the `UpdateInstallResult` doc, `app/packages/shared/src/autoUpdateSetting.ts:86-91`) (gap: `app/packages/desktop-main/src/updater.ts:242-256` calls `quitAndInstall` unconditionally)

## IPC channel contract

- [x] **APP-UPDATE-IPC-001**: Desktop-main shall expose the update surface only as the five Electron IPC channels `iac.settings.autoUpdate.get`, `.update`, `.check`, `.download` and `.install`, with no HTTP transport. (observed; CLAUDE.md invariant "The desktop app has no HTTP transport")
- [x] **APP-UPDATE-IPC-002**: When any of the five `iac.settings.autoUpdate.*` handlers is invoked, it shall first log `IacSettingsController: <pattern> invoked` at debug level with no payload contents. (observed; `.claude/rules/logging.md`)
- [x] **APP-UPDATE-IPC-003**: When the renderer invokes `iac.settings.autoUpdate.check`, desktop-main shall return the manual check's `ManualUpdateCheckResult` (no update, update available with version, or error). (OpenSpec: auto-update-scaffold / Operator can trigger an on-demand update check)
- [x] **APP-UPDATE-IPC-004**: When the renderer invokes `iac.settings.autoUpdate.download` in a real Electron main process, desktop-main shall immediately return `{ started: true, streamId }`, push each progress sample tagged with that `streamId` on `iac.settings.autoUpdate.download.chunk`, and send exactly one terminal message on `iac.settings.autoUpdate.download.end` carrying `version` on success or `error` on failure. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-IPC-005**: Desktop-main shall register `iac.settings.autoUpdate.download` as a self-bridged `ipcMain.handle` channel (listed in `SELF_BRIDGED_PATTERNS`) so the handler receives the invoking `WebContents`, and shall skip that registration outside Electron. (observed)
- [x] **APP-UPDATE-IPC-006**: If the invoking renderer's `WebContents` is destroyed during an update download, then desktop-main shall stop sending chunk and end messages for that stream. (observed)
- [x] **APP-UPDATE-IPC-007**: When the renderer invokes `iac.settings.autoUpdate.install`, desktop-main shall return the install step's `UpdateInstallResult`. (OpenSpec: auto-update-scaffold / Operator can download and install an available update, from add-user-initiated-update-install)
- [x] **APP-UPDATE-IPC-008**: The preload bridge shall surface the update download as an async iterable of `UpdateDownloadProgress` that completes on a successful end message and throws with the end message's `error` on failure. (observed)
- [ ] **APP-UPDATE-IPC-009**: The `iac.settings.autoUpdate.download.chunk` and `.download.end` channel names shall be declared in one shared place consumed by both desktop-main and preload. (observed) (gap: declared twice, `app/packages/desktop-main/src/controllers/iac-settings.controller.ts:35-38` and `app/packages/desktop-preload/src/preload.ts:156-160`)

## Release workflow: trigger and range

- [x] **APP-UPDATE-REL-001**: The release workflow shall run only on manual `workflow_dispatch`, accepting optional `from`, `to`, `bump` (`auto|major|minor|patch`, default `auto`), `skip_bump` and `tag` inputs. (OpenSpec: release-automation / Manual release trigger with configurable range)
- [x] **APP-UPDATE-REL-002**: When the release workflow runs in bump mode with no `from` input, it shall compute the changelog and bump over the range from the newest `v*` tag reachable from `to^` to `to`, with `to` defaulting to main's tip. (OpenSpec: release-automation / Manual release trigger with configurable range)
- [x] **APP-UPDATE-REL-003**: When the release workflow runs with an explicit `from` input, it shall compute the changelog and bump only over `from..to`, ignoring existing tags. (OpenSpec: release-automation / Manual release trigger with configurable range)
- [x] **APP-UPDATE-REL-004**: If the release workflow runs in bump mode and the resolved `to` commit is not main's current tip, then it shall fail before generating a changelog, directing the operator to replay mode. (observed; supersedes the OpenSpec "Trigger with explicit range" allowance for an arbitrary `to`, see Dropped)
- [x] **APP-UPDATE-REL-005**: When the release workflow runs with no `from` input and no `v*` tag is reachable, it shall compute the changelog over the full history up to `to`, including the root commit. (OpenSpec: release-automation / Manual release trigger with configurable range)
- [x] **APP-UPDATE-REL-006**: If the release workflow runs with `skip_bump` true and no `tag`, then it shall fail in its first step before any changelog generation or release publication. (OpenSpec: release-automation / Skip-bump replay mode)

## Release workflow: version bump and tag

- [x] **APP-UPDATE-BUMP-001**: When the release workflow's bump strategy is `auto` and the range contains a commit marked breaking (`!` before the colon or a `BREAKING CHANGE:` footer), git-cliff shall compute a major bump. (OpenSpec: release-automation / Automatic semver bump from Conventional Commits)
- [x] **APP-UPDATE-BUMP-002**: When the release workflow's bump strategy is `auto` and the range contains `feat` commits and no breaking markers, git-cliff shall compute a minor bump. (OpenSpec: release-automation / Automatic semver bump from Conventional Commits)
- [x] **APP-UPDATE-BUMP-003**: When the release workflow's bump strategy is `auto` and the range contains only non-`feat`, non-breaking Conventional Commits, git-cliff shall compute a patch bump. (OpenSpec: release-automation / Automatic semver bump from Conventional Commits)
- [x] **APP-UPDATE-BUMP-004**: When the release workflow receives an explicit `bump` of `major`, `minor` or `patch`, it shall use that bump instead of the computed one. (OpenSpec: release-automation / Automatic semver bump from Conventional Commits)
- [x] **APP-UPDATE-BUMP-005**: When no `v*` tag exists yet, the release workflow's bump computation shall produce `v0.1.0` as the first tag. (observed)
- [x] **APP-UPDATE-BUMP-006**: When a bump-mode release run computes a version different from the root `package.json`, it shall set only the root manifest's version (`--workspaces=false`), commit `package.json` and `package-lock.json` as `chore(release): <tag>`, push to protected `main`, and push an annotated tag of the same name, all as the release GitHub App's bot identity rather than `GITHUB_TOKEN`. (OpenSpec: release-automation / Versioned commit and tag pushed to the protected default branch)
- [x] **APP-UPDATE-BUMP-007**: If the computed version already equals the root `package.json` version, or the tag already exists on origin, then the release workflow shall skip that commit or tag step instead of failing. (observed)
- [x] **APP-UPDATE-BUMP-008**: The release workflow shall check out with `persist-credentials: false` and supply the GitHub App token only as a request-scoped header on the bump and tag pushes, so the token is never on disk during the AI summary step. (observed)
- [x] **APP-UPDATE-BUMP-009**: The release changelog shall omit `chore(release):` commits. (observed)
- [x] **APP-UPDATE-BUMP-010**: When a bump-mode release run pushes a tag, the same workflow run shall build and package that tag on Linux, macOS and Windows rather than relying on a separate tag-triggered run. (OpenSpec: release-automation / Versioned commit and tag pushed to the protected default branch)
