# Desktop Shell Specs

EARS requirements for prefix `APP-SHELL`; design and rationale live in `docs/intent/operator-app/desktop-shell/desktop-shell-design.md`.

## Process Start and Composition Root

- [x] **APP-SHELL-BOOT-001**: When the desktop-main module loads on macOS or Linux, the desktop app shall re-read the login shell `PATH` before any child process is spawned, and on Windows shall leave `PATH` unchanged (`main.ts:12`, `fix-path-bootstrap.ts:17-18`). (observed)
- [x] **APP-SHELL-BOOT-002**: If desktop-main is started outside an Electron main process (no `process.versions.electron`), then desktop-main shall throw a readable error before calling any Electron API (`main.ts:18-23`). (observed; the no-HTTP transport requirement itself belongs to `APP-IPC`)
- [x] **APP-SHELL-BOOT-003**: When desktop-main starts inside Electron, it shall create the winston logger under `<userData>/logs` before bootstrapping the Nest container (`main.ts:25-26`). (observed)
- [x] **APP-SHELL-BOOT-004**: The desktop app shall remove Electron's default application menu so the main window shows no File/Edit/View/Window menu bar (`electron-entry.ts:206-208`). (observed)
- [x] **APP-SHELL-BOOT-005**: When Electron reports ready, the desktop app shall bootstrap the Nest IPC microservice, register the global RPC error filter before `listen()`, and only then create and attach the main window (`electron-entry.ts:210-228`, `main.ts:43-56`). (observed)
- [x] **APP-SHELL-BOOT-006**: If the Nest IPC bootstrap rejects, then the desktop app shall quit rather than open a window with no back end (`electron-entry.ts:242-245`). (observed)
- [x] **APP-SHELL-BOOT-007**: If the main window's renderer fails to load (dev server URL or packaged `out/renderer/index.html`), then the desktop app shall quit (`electron-entry.ts:193-201`). (observed)
- [ ] **APP-SHELL-BOOT-008**: If a main-process start-up or window step fails (external-link open, renderer load, updater init, Nest bootstrap), then the desktop app shall record the failure in the winston log file, not only on `console.error`. (observed; gap: `electron-entry.ts:49,199,222,243`)
- [x] **APP-SHELL-BOOT-009**: The main `BrowserWindow` shall be created with `contextIsolation: true`, `sandbox: true` and the preload bundle at `out/preload/preload.cjs` (`electron-entry.ts:175-184`). (observed)
- [x] **APP-SHELL-BOOT-010**: When renderer content in the main window requests a new window (a `target="_blank"` link or `window.open`), the desktop app shall deny the new Electron window and open the URL in the operator's default OS browser (`electron-entry.ts:46-53`). (observed)
- [x] **APP-SHELL-BOOT-011**: When the macOS dock icon re-activates the app with no windows open, the desktop app shall create a new main window and re-attach it to `WindowService` (`electron-entry.ts:236-240`). (observed)
- [x] **APP-SHELL-BOOT-012**: When the last window closes on Windows or Linux, the desktop app shall quit; on macOS it shall keep running (`electron-entry.ts:250-252`). (observed)
- [x] **APP-SHELL-BOOT-013**: The `DIAGNOSTICS_LOG_DIR` provider in `AppModule` shall resolve to `<userData>/logs` under Electron and to the `DIAGNOSTICS_LOG_DIR` env var or `os.tmpdir()` under plain Node, so the integration-test server can build the same container without Electron (`app.module.ts:102-112`). (observed)
- [x] **APP-SHELL-BOOT-014**: `desktop:build` shall fail when `@pulumi/*` or `semver` are inlined into the main-process bundle instead of left external (root `package.json:46`, `build/verify-main-bundle-externals.mjs`). (observed)
- [x] **APP-SHELL-BOOT-015**: When the Nest IPC bootstrap succeeds, the desktop app shall install the helper quit hook with the container's `HelperSessionRegistry` after starting the updater and before creating the main window. (observed: `electron-entry.ts:221-228`; the hook's behaviour is specified by `helper-task`)
- [x] **APP-SHELL-BOOT-016**: The desktop main process shall open native directory, multi-file and save dialogs only through the `NativeDialogService` exported by `NativeDialogModule`, and outside Electron each dialog shall resolve to its cancelled value (`null` or `[]`) without importing `electron`. (observed: `NativeDialogService.ts:22-56`, `native-dialog.module.ts:8-12`)

- [x] **APP-SHELL-BIND-003**: Each store bound by the composition root (secrets, remote file, audit log, Discord config, run record) shall receive a lazy config resolver rather than a resolved config, so the Nest container builds on a fresh install that has no stack outputs (`cloud-provider.module.ts:196-209`). (observed)
- [x] **APP-SHELL-BIND-004**: While the stack has no `runsTableName` output (before the first apply), the run-record store's config resolver shall fall back to the runs-table name derived from the remote file store (`cloud-provider.module.ts:174-175`). (observed; whether `RunService` takes the lock in that window is owned by `IAC-RUN`)

## Window-Control IPC

- [x] **APP-SHELL-WINIPC-001**: When the renderer invokes the `window.minimize` channel, desktop-main shall minimize the attached main window (`window.controller.ts:16-20`, `WindowService.ts:55-62`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-002**: When the renderer invokes the `window.toggleMaximize` channel and the main window is not maximized, desktop-main shall maximize it (`window.controller.ts:23-27`, `WindowService.ts:69-80`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-003**: When the renderer invokes the `window.toggleMaximize` channel and the main window is maximized, desktop-main shall restore it to its unmaximized size and position (`WindowService.ts:72-73`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-004**: When the renderer invokes the `window.close` channel, desktop-main shall close the attached main window (`window.controller.ts:30-34`, `WindowService.ts:83-90`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-005**: When the renderer invokes the `window.isMaximized` channel, desktop-main shall return the attached main window's current maximized state (`window.controller.ts:37-41`, `WindowService.ts:98-106`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-006**: When the attached main window emits a native `maximize` or `unmaximize` event for any reason (toggle channel, header double-click, OS snap), desktop-main shall push `window.maximizedChange` with the new state to the renderer over `webContents.send` (`WindowService.ts:32-33,117-124`). (OpenSpec: custom-title-bar / Window-control IPC channels)
- [x] **APP-SHELL-WINIPC-007**: While no main window is attached to `WindowService`, the `window.minimize`, `window.toggleMaximize` and `window.close` channels shall do nothing and `window.isMaximized` shall return `false` (`WindowService.ts:56,70,84,99`). (observed)
- [x] **APP-SHELL-WINIPC-008**: When the attached main window emits `closed`, `WindowService` shall drop its reference only if that window is still the attached one, so a newer re-attached window is not detached (`WindowService.ts:46-48`). (observed)
- [x] **APP-SHELL-WINIPC-009**: If a `WindowService` window operation throws, then `WindowService` shall log the normalized message at `warn` and return without rethrowing, with `isMaximized` returning `false` (`WindowService.ts:49-51,59-61,77-79,87-89,102-105,121-123`). (observed)
- [x] **APP-SHELL-WINIPC-010**: When any of the four `window.*` request channels is invoked, `WindowController` shall first log `WindowController: <channel> invoked` at debug level (`window.controller.ts:18,25,32,39`). (observed; `.claude/rules/logging.md`)
- [x] **APP-SHELL-WINIPC-011**: When the renderer reads `window.hyveon.window.platform`, the preload shall return the OS platform identifier from `process.platform` without an IPC round-trip (`desktop-preload/src/preload.ts:645`). (OpenSpec: custom-title-bar / Preload exposes window platform and controls)
- [x] **APP-SHELL-WINIPC-012**: When the renderer calls `window.hyveon.window.minimize()`, `toggleMaximize()`, `close()` or `isMaximized()`, the preload shall invoke the matching `window.*` channel and resolve with its result (`desktop-preload/src/preload.ts:646-649`). (OpenSpec: custom-title-bar / Preload exposes window platform and controls)
- [x] **APP-SHELL-WINIPC-013**: When the renderer subscribes with `window.hyveon.window.onMaximizedChange(callback)`, the preload shall call the callback on every `window.maximizedChange` push and return an unsubscribe function that removes the listener (`desktop-preload/src/preload.ts:650`). (OpenSpec: custom-title-bar / Preload exposes window platform and controls)

## Polling Heartbeat

- [x] **APP-SHELL-POLL-001**: When a named poller is registered with the polling provider, the provider shall run it once immediately and then every `intervalMs` (`polling-provider.component.tsx:152-180`). (observed)
- [x] **APP-SHELL-POLL-002**: If a poller is already in flight when its timer fires or it is refreshed manually, then the polling provider shall skip that run rather than start a concurrent fetch (`polling-provider.component.tsx:113-116`). (observed)
- [x] **APP-SHELL-POLL-003**: When the polling provider starts any run of a poller (timer, `refresh` or `refreshAll`), it shall restart that poller's interval so the next automatic run lands one full interval later (`polling-provider.component.tsx:117-118`). (observed)
- [x] **APP-SHELL-POLL-004**: If a poller's function throws, then the polling provider shall record the error in that poller's state and keep polling, without rethrowing; a later success shall clear the error (`polling-provider.component.tsx:133-145`). (observed)
- [x] **APP-SHELL-POLL-005**: When a poller is registered under a name that is already registered, the polling provider shall replace the previous registration, clear its timer, and keep its first-attempt, last-attempt and last-success timestamps (`polling-provider.component.tsx:154-178`). (observed)
- [x] **APP-SHELL-POLL-006**: When a poller registration's cleanup runs, the polling provider shall remove the poller only if that registration still owns the name (`polling-provider.component.tsx:182-194`). (observed)
- [x] **APP-SHELL-POLL-007**: The polling provider shall treat a poller as stale once more than 2 x its `intervalMs` has passed since its last success, or since its first attempt if it has never succeeded (`polling-provider.component.tsx:67,303-315`). (observed)
- [x] **APP-SHELL-POLL-008**: While the routed shell is mounted, the polling provider shall publish a 1 Hz `now` heartbeat in a state context separate from its stable `register`/`refresh`/`refreshAll` actions context, so relative-time labels and staleness re-evaluate without each consumer running a timer (`polling-provider.component.tsx:210-215,229-234`). (observed)
- [x] **APP-SHELL-POLL-009**: Where `usePoller` is called with `enabled` false, the hook shall not register the poller; it shall re-register only when `name`, `intervalMs` or `enabled` change, always calling the latest `fn` (`polling-provider.component.tsx:273-301`). (observed)
